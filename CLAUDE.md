# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Public documentation site for DeployCode, built with Fumadocs on Next.js (App Router). The product
itself lives in the sibling repository `../deploycode`. This repo holds only the docs.

## Commands

```bash
pnpm install
pnpm dev            # http://localhost:3000
pnpm build          # the only check that parses every MDX/frontmatter file
pnpm lint           # Biome (lint + format check), also formats meta.json
pnpm format         # Biome format --write
pnpm types:check    # next typegen && tsc --noEmit
```

There are no tests. Before calling a content change done, run `pnpm build`. `lint` and
`types:check` do not parse MDX frontmatter. An unquoted YAML value containing `: ` (for example
`description: Деплой статики: Vite`) passes both and only fails at build time with
`YAMLParseError: Nested mappings are not allowed`. Quote such values.

pnpm 11 enforces a minimum release age. Packages newer than that are listed under
`minimumReleaseAgeExclude` in `pnpm-workspace.yaml`, and `allowBuilds` there whitelists esbuild's
postinstall.

Next.js here is 16.x and may differ from training data. Before writing Next-specific code, check
the bundled guides in `node_modules/next/dist/docs/`. `AGENTS.md` carries the same rule and is
re-generated by `next dev`, so keep it committed rather than deleting it.

## Deployment

Deployed through DeployCode itself (dogfooding), not a pipeline in this repo: Railpack builds the
app with no Dockerfile and runs `pnpm run start` (`next start`, port 3000, which matches the
default container port of a DeployCode domain). Anything that changes how the app builds or starts
(`packageManager`, `engines.node`, the `build`/`start` scripts, pnpm settings in
`pnpm-workspace.yaml`) affects production builds. Verify such changes with a local Railpack build;
the steps are in `README.md`. `siteUrl` in `lib/shared.ts` defaults to the production address, so
no environment variables are required.

## Architecture

- **Content source**: `lib/source.ts` uses `defineDocs` from `fumadocs-mdx/macro`. There is no
  `source.config.ts`; collections and schemas are declared inline there. Generated output goes to
  `.source/` (gitignored). `lucideIconsPlugin` resolves `icon:` strings in frontmatter and
  `meta.json` to Lucide icons by name.
- **UI package alias**: `fumadocs-ui` is `npm:@fumadocs/base-ui`, the Base UI variant that matches
  the product's `@base-ui/react`. Import from `fumadocs-ui/...` as usual.
- **Routes**: `app/docs/[[...slug]]` renders pages. `app/og/docs/[...slug]` renders OG images.
  `app/llms.txt`, `app/llms-full.txt` and `app/llms.mdx/docs/[[...slug]]` serve Markdown for LLMs.
  `app/api/search` serves Orama search with the default multilingual tokenizer, which handles
  Cyrillic, so no `language` option is set. URL builders for these routes live in `lib/shared.ts`.
- **Markdown negotiation**: `proxy.ts` (Next 16 middleware) rewrites `/docs/foo.md`, and
  `/docs/foo` requested with `Accept: text/markdown`, to the `llms.mdx` route.
- **Localization**: the site is Russian only, with no Fumadocs i18n routing. UI strings are
  overridden through `RootProvider i18n={{ locale: 'ru', translations: ru }}` with `lib/i18n.ts`,
  typed against `Translations` from `fumadocs-ui/i18n`.
- **MDX components**: `components/mdx.tsx` registers the defaults plus Accordion(s), Steps/Step,
  Tabs/Tab and `Status`. Any new MDX component must be added there.
- **Branding**: `components/logo.tsx` inlines the product logo with `currentColor`. The original
  SVG in `../deploycode/apps/web/public` is white-only and disappears in light theme. Header links
  and the GitHub URL come from `lib/layout.shared.tsx` and `lib/shared.ts` (`appUrl` is the control
  panel, `https://app.deploycode.ru`).

## Content structure

- Pages live in `content/docs/**.mdx`. Sidebar order and group titles come from `meta.json` files.
  The root `meta.json` uses `---Title---` separators to form sidebar groups, and each folder's
  `meta.json` sets its title, icon and page order. A page missing from its folder's `pages` array
  still builds and is reachable by URL, but it does **not** appear in the sidebar. Always add new
  pages to `pages`.
- `structure/` (Организации и проекты) documents the core hierarchy
  организация → проект → окружение → сервис and the scope page.
- Use `<Status value="in-progress" | "api-only" | "roadmap" />` (`components/status.tsx`) to mark
  feature readiness. Only add it when the main repo confirms the status.
- Internal links are absolute (`/docs/...`). Heading anchors are Cyrillic slugs
  (`#сеть-и-порты`). After renaming or moving pages, grep `content/` and `app/` for the old paths;
  `app/(home)/page.tsx` also links into the docs.

## Writing rules

- All user-facing text is in Russian. Code comments may be in Russian, as in existing files.
- Terminology follows the glossary in `../deploycode/CONTEXT.md`. Keep the Russian terms already
  used in the docs: Организация, Проект, Окружение, Сервис, Приложение, Деплой, Запрос на деплой,
  Артефакт, Готовность деплоя. Scope is «Область (scope)»; the glossary rejects "context" and
  "filter" as names for it.
- The hierarchy mirrors a kubectl context/namespace: the selected scope filters every workspace
  page. Present this as an analogy only. The runtime is Docker Swarm, not Kubernetes.
- Do not position DeployCode by comparison to Vercel or other competitors. Describe it on its own
  terms: a SaaS control plane run by DeployCode, with apps and data on servers in the customer's
  own cloud. There is no self-hosted or on-prem edition.
- Verify product facts in `../deploycode` (DB schema in `packages/server/src/db/schema`, server
  setup in `packages/server/src/setup`, feature status in
  `.claude/skills/project-knowledge/references/project.md`) instead of inferring them. Example:
  servers connect as a non-root user that **requires passwordless sudo**, not "without root
  privileges". When a detail is unknown, leave a stub heading or `<Callout>Скоро.</Callout>`
  rather than inventing it.
