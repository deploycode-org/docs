## Архитектура

DeployCode разделён на две части:

- **Панель управления** (control plane) — веб-интерфейс, API и очередь развёртываний. Её размещает и
  обслуживает команда DeployCode.
- **Ваши серверы** — виртуальные машины в вашем облачном аккаунте. На них собираются образы и работают
  приложения, базы данных и reverse proxy (Traefik).

DeployCode не размещает ваши приложения у себя: даже если панель создаёт ВМ за вас (например, в
Yandex Cloud), машина находится в вашем облачном аккаунте.

## Путь от коммита до приложения

1. Вы пушите в ветку сервиса с включённым [авторазвёртыванием](/docs/deployments/github#авторазвёртывание)
   или нажимаете **«Развернуть»** на странице сервиса.
2. Панель фиксирует **запрос на развёртывание** вместе с конфигурацией и ставит задачу в очередь.
3. Воркер подключается к серверу по SSH и собирает образ с помощью Railpack.
4. Docker Swarm запускает новую версию; Traefik направляет на неё трафик.
5. Панель ждёт **готовности развёртывания** и сохраняет результат.

Сервис из [Docker-образа](/docs/deployments/docker-image) или [шаблона](/docs/deployments/templates) не
собирается: вместо шага сборки образ скачивается на сервер. Такой сервис развёртывается кнопкой
«Развернуть» или вебхуком реестра, если включено
[автообновление](/docs/deployments/docker-image#автообновление).

## Зоны ответственности

| Что | Отвечает |
| --- | --- |
| Панель, очередь развёртываний, интеграция с GitHub | DeployCode |
| Серверы, облачный аккаунт, данные в томах | Вы |
| Внешние DNS, git и облачные провайдеры | Провайдер |
