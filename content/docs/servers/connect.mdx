---
title: Подключение сервера
description: Мастер добавления своего VPS или сервера в облаке.
---

Новый сервер добавляется в разделе **Ресурсы → Серверы** кнопкой **«Добавить сервер»**, пунктом **«Сервер»**
в окне [«Что создать?»](/docs/structure/services#окно-что-создать) или прямо из мастера
[«Новый проект» или «Новый сервис»](/docs/quick-start#сервер).

На странице **«Новый сервер»** шаги мастера перечислены слева, а справа видна сводка выбранной
конфигурации. Внизу карточки шага — счётчик «Шаг N из M» и кнопка **«Назад»**.

## Где разместить сервер

| Вариант | Когда выбрать |
| --- | --- |
| **Свой сервер** | Уже есть VPS у любого провайдера: нужны IP-адрес, SSH-порт и доступ под `root` или пользователем с sudo без пароля |
| **reg.ru Cloud** | DeployCode создаст ВМ в вашем аккаунте reg.ru Cloud ([подробнее](/docs/servers/regru-cloud)) |
| **Yandex Cloud** | DeployCode создаст ВМ в вашем каталоге Yandex Cloud ([подробнее](/docs/servers/yandex-cloud)) |

Облачные варианты становятся доступны после подключения облака в разделе **«Облачные провайдеры»**.
Подключать облака могут владелец и администраторы. Если облако выбрать нельзя, подсказка на его карточке
объясняет, почему, а ссылка под карточкой ведёт к решению:

| Под карточкой | Когда |
| --- | --- |
| **«Подключить …»** | Облако не подключено. Ссылка открывает страницу облачных провайдеров сразу на нужном облаке |
| **«Исправить подключение»** | Облако подключено, но провайдер не принимает ключ или токен DeployCode, см. [reg.ru Cloud](/docs/servers/regru-cloud#проверка-подключения) и [Yandex Cloud](/docs/servers/yandex-cloud#проверка-подключения) |
| **«Перейти в „…“»** | Облако подключено в другой вашей организации, где вы владелец или администратор. Ссылка переключает организацию |

Selectel и VK Cloud помечены «скоро»: создавать в них серверы из DeployCode пока нельзя. Сервер, который у
вас там уже есть, подключите как **«Свой сервер»**.

## Свой сервер

<Steps>
<Step>

### Данные сервера

| Поле | Что указать |
| --- | --- |
| Название | Как сервер будет называться в панели |
| Тип сервера | **Deploy · Сервер развёртывания** — для приложений и баз; **Build · Сервер сборки** — только собирает образы ([подробнее](/docs/servers#типы-серверов)) |
| Принадлежность | Вся организация или конкретный проект |
| IP-адрес | Публичный адрес сервера |
| SSH-порт | По умолчанию `22` |
| SSH-пользователь | `root` (по умолчанию) или пользователь с sudo без пароля. На ВМ Yandex Cloud это обычно `ubuntu`, на reg.ru — `root` |

Пароль и приватный ключ вводить не нужно: DeployCode сам создаст SSH-ключ для этого сервера.

Конфигурацию своего сервера вы выбираете сами. Рекомендуем от 4 ГБ RAM, SSD от 40 ГБ и не меньше 12 ГБ
свободного места, см. [Требования](/docs/servers/requirements).

Если сервера ещё нет, ссылка **«Создать его в облаке»** возвращает к выбору облака: адрес, ключ и установку
DeployCode сделает сам.

</Step>
<Step>

### Выполните команду на сервере

Панель покажет одноразовую команду:

```bash
curl -fsSL https://app.deploycode.ru/api/setup/<токен> | bash
```

Выполните её на сервере **под тем пользователем, которого указали в форме**: команда добавит публичный ключ
DeployCode в его `~/.ssh/authorized_keys` и сообщит панели, что сервер готов к подключению. Мастер перейдёт
к следующему шагу сам. Проверить сразу можно кнопкой **«Проверить подключение»**.

Токен действует **30 минут**. Если он истёк, выпустите новый кнопкой **«Выпустить новый токен»** —
пересоздавать сервер не нужно.

</Step>
<Step>

### Настройка сервера

DeployCode подключится по SSH и подготовит сервер: установит Docker, инициализирует Docker Swarm, запустит
[Traefik](/docs/networking), установит Railpack и rclone. Ход установки виден в логе на этом шаге.

Если вы подключились не под `root`, установка целиком выполняется через sudo. В конце DeployCode добавляет
вашего пользователя в группу `docker` и отдаёт ему рабочий каталог, поэтому развёртывания потом идут под этим
пользователем без sudo.

Сервер сборки настраивается короче: Docker, Docker Buildx, Git, Railpack и каталоги для сборки. Swarm,
Traefik и rclone на нём не нужны. Если Buildx не удалось поставить из репозитория дистрибутива, настройка
остановится с ошибкой: подключите совместимый репозиторий Docker, установите плагин Buildx и повторите
настройку.

Когда всё готово, появится сообщение **«Сервер готов»**. Если что-то пошло не так, исправьте причину по логу
и нажмите **«Повторить настройку»**. Уже установленное не переустанавливается, а запущенные сервисы не
затрагиваются.

</Step>
</Steps>

## Если установка не завершена

Сервер, на котором DeployCode ещё не установлен, развёртывания не принимает, см.
[Готовность к развёртыванию](/docs/servers#готовность-к-развёртыванию). Продолжить можно с того места, где
остановились:

| Где остановились | Что сделать |
| --- | --- |
| Команду подключения ещё не выполнили | **«Продолжить подключение»** в меню сервера или на его странице. Мастер вернётся к команде, а если токен истёк, предложит выпустить новый |
| Команду выполнили, установку не запустили или она завершилась ошибкой | На странице сервера статус **«Не настроен»** или **«Ошибка»**, кнопка **«Перейти к установке»** открывает вкладку **«Проверка»**. Там установку запускает **«Запустить установку»**, а после ошибки — **«Восстановить настройки»** |
| Установка ещё идёт | На странице сервера статус **«Устанавливается»**, журнал — во вкладке **«Активность»**. Второй запуск не нужен: кнопки установки недоступны, пока идёт первая |

## Проверка готовности

На странице сервера, во вкладке **«Проверка»**, видно, всё ли установлено:

| Проверка | Что значит |
| --- | --- |
| Docker установлен | Docker Engine есть на сервере |
| RClone установлен | Нужен для резервных копий (не проверяется у серверов сборки) |
| Railpack установлен | Нужен для сборки |
| Docker Buildx доступен | Нужен для сборки образов (проверяется только у серверов сборки) |
| Docker Swarm инициализирован | Нужен для запуска сервисов (не проверяется у серверов сборки) |
| Сеть создана | Общая сеть сервисов и Traefik (не проверяется у серверов сборки) |
| Основная директория создана | Каталог DeployCode на сервере |
| Режим привилегий | «Запущен от root» или «Запущен с sudo». «Нет sudo-доступа» — ошибка |
| Группа Docker | Пользователь SSH может работать с Docker без sudo |

Если DeployCode на сервере ещё не устанавливался, кнопка называется **«Запустить установку»**. Если установка уже
была, кнопка называется **«Восстановить настройки»**: она заново запускает настройку сервера, когда не прошла
хотя бы одна проверка. У сервера
сборки она заново настраивает Docker, Git, Railpack и каталоги сборки и проверяет Docker Buildx. Ход
установки виден здесь же, а журнал последней установки остаётся во вкладке
[«Активность»](/docs/servers#логи-установки).

## Ресурсы и диск

На странице сервера есть карточка **«Ресурсы сервера»** — CPU, память, диск, иноды и Docker — и
**«Очистка диска»** для кеша сборок, неиспользуемых образов и томов. О порогах свободного места — в
[Требованиях](/docs/servers/requirements#диск).
