---
title: Подключение сервера
description: Мастер добавления своего VPS или сервера в облаке.
---

Новый сервер добавляется в разделе **Ресурсы → Серверы** кнопкой **«Добавить сервер»** или прямо из
мастера [первого запуска](/docs/quick-start).

## Где разместить сервер

| Вариант | Когда выбрать |
| --- | --- |
| **Свой сервер** | Уже есть VPS у любого провайдера: нужны IP-адрес, SSH-порт и root-доступ |
| **reg.ru Cloud** | DeployCode создаст VPS в вашем аккаунте reg.ru Cloud ([подробнее](/docs/servers/regru-cloud)) |
| **Yandex Cloud** | DeployCode создаст машину в вашем каталоге Yandex Cloud ([подробнее](/docs/servers/yandex-cloud)) |

Облачные варианты становятся доступны после подключения облака в разделе **«Облачные провайдеры»**.

## Свой сервер

<Steps>
<Step>

### Данные сервера

| Поле | Что указать |
| --- | --- |
| Название | Как сервер будет называться в панели |
| Тип сервера | **Deploy · Сервер развёртывания** — для приложений и баз; **Build · Сервер сборки** — только собирает образы ([подробнее](/docs/servers#типы-серверов)) |
| Принадлежность | Вся организация или конкретный проект |
| IP-адрес | Публичный адрес сервера |
| SSH-порт | По умолчанию `22` |
| SSH-пользователь | `root` (по умолчанию) или пользователь с sudo без пароля |

Пароль и приватный ключ вводить не нужно: DeployCode сам создаст SSH-ключ для этого сервера.

Конфигурацию своего сервера вы выбираете сами. Рекомендуем от 4 ГБ RAM, SSD от 40 ГБ и не меньше 12 ГБ
свободного места, см. [Требования](/docs/servers/requirements).

</Step>
<Step>

### Выполните команду на сервере

Панель покажет одноразовую команду:

```bash
curl -fsSL https://app.deploycode.ru/api/setup/<токен> | bash
```

Выполните её на сервере **под тем пользователем, которого указали в форме**: команда добавит публичный ключ
DeployCode в его `~/.ssh/authorized_keys` и сообщит панели, что сервер готов к подключению. Мастер перейдёт
к следующему шагу сам.

Токен действует **30 минут**. Если он истёк, выпустите новый кнопкой **«Выпустить новый токен»**.

</Step>
<Step>

### Настройка сервера

DeployCode подключится по SSH и подготовит сервер: установит Docker, инициализирует Docker Swarm, запустит
[Traefik](/docs/networking), установит Railpack и rclone. Ход установки виден в логе на этом шаге.

Сервер сборки настраивается короче: Docker, Docker Buildx, Git, Railpack и каталоги для сборки. Swarm,
Traefik и rclone на нём не нужны. Если Buildx не удалось поставить из репозитория дистрибутива, настройка
остановится с ошибкой: подключите совместимый репозиторий Docker, установите плагин Buildx и повторите
настройку.

Когда всё готово, появится сообщение **«Сервер готов»**. Если что-то пошло не так, исправьте причину по логу
и нажмите **«Повторить настройку»** — настройка безопасна для повторного запуска.

</Step>
</Steps>

## Проверка готовности

На странице сервера, во вкладке **«Проверка»**, видно, всё ли установлено:

| Проверка | Что значит |
| --- | --- |
| Docker установлен | Docker Engine есть на сервере |
| RClone установлен | Нужен для резервных копий (не проверяется у серверов сборки) |
| Railpack установлен | Нужен для сборки |
| Docker Buildx доступен | Нужен для сборки образов (проверяется только у серверов сборки) |
| Docker Swarm инициализирован | Нужен для запуска сервисов (не проверяется у серверов сборки) |
| Сеть создана | Общая сеть сервисов и Traefik (не проверяется у серверов сборки) |
| Основная директория создана | Каталог DeployCode на сервере |
| Режим привилегий | «Запущен от root» или «Запущен с sudo». «Нет sudo-доступа» — ошибка |
| Группа Docker | Пользователь может работать с Docker |

Кнопка **«Восстановить настройки»** заново запускает настройку сервера, если какая-то проверка не прошла.
У сервера сборки она заново настраивает Docker, Git, Railpack и каталоги сборки и проверяет Docker Buildx.

## Ресурсы и диск

На странице сервера есть карточка **«Ресурсы сервера»** — CPU, память, диск, иноды и Docker — и
**«Очистка диска»** для кеша сборок, неиспользуемых образов и томов. О порогах свободного места — в
[Требованиях](/docs/servers/requirements#диск).
