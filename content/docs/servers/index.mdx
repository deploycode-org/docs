**Сервер** — машина в вашем облаке или у любого хостинга, на которой DeployCode собирает образы и запускает
сервисы. Панель подключается к нему по SSH под `root` или пользователем с sudo без пароля.

Серверы находятся в разделе **Ресурсы → Облачные сервера**.

## Типы серверов

| Тип | Что делает |
| --- | --- |
| Сервер развёртывания | Собирает и запускает сервисы. Именно его выбирают при создании сервиса |
| Сервер сборки | Только собирает образы, сервисы на нём не работают |

<Callout type="info">
  Назначить приложению отдельный сервер сборки в панели пока нельзя: приложения собираются на своём сервере
  развёртывания.
</Callout>

## Список серверов

| Статус | Что значит |
| --- | --- |
| Подключается | Сервер создаётся или ждёт выполнения команды подключения |
| Активен | Сервер на связи |
| Недоступен | Сервер не отвечает по SSH |
| Удалён у провайдера | Облако сообщило, что машины больше нет |
| Ошибка | Подключение или настройка не удались — см. вкладку «Проверка» |

В списке также видны свободное место на диске, способ подключения и сколько сервисов работает на сервере.
В меню сервера — **«Проверить доступность»**, **«Продолжить подключение»** и **«Удалить сервер»**.

## Страница сервера

| Вкладка | Что в ней |
| --- | --- |
| Обзор | Параметры подключения, последние развёртывания, **«Ресурсы сервера»** и **«Очистка диска»** |
| Проверка | [Проверка готовности](/docs/servers/connect#проверка-готовности) и **«Восстановить настройки»** |
| Безопасность | SSH-ключ, привилегии пользователя, статус подключения |
| Активность | История операций |
| Терминал | [SSH-сессия на сервере](/docs/observability/logs#терминал-сервера) |

### Ресурсы и очистка диска

**«Ресурсы сервера»** показывают ОС, CPU, память, диск, иноды и Docker и обновляются раз в минуту. Там же
видно, сколько места можно освободить. Пороги свободного места — в [Требованиях](/docs/servers/requirements#диск).

**«Очистка диска»**:

| Вариант | Что удаляется |
| --- | --- |
| Безопасная очистка | Кеш сборок, остановленные контейнеры, промежуточные слои. Образы и тома не трогаются |
| Кеш сборок | Кеш BuildKit и Railpack — следующая сборка будет дольше |
| Остановленные контейнеры | Только остановленные контейнеры |
| Неиспользуемые образы | Образы без контейнеров — сервисы, возможно, придётся пересобрать |
| Полная очистка (system prune) | Всё перечисленное и неиспользуемые сети. Тома не трогаются |
| Неиспользуемые тома | ⚠️ Может удалить данные остановленного сервиса, например базы |

## Доступность

DeployCode проверяет серверы по SSH каждые 10 минут. После трёх неудачных проверок подряд (около 30 минут)
сервер получает статус **«Недоступен»**, а развёртывание на него блокируется. Как только сервер ответит,
статус вернётся сам. Проверить сразу можно кнопкой **«Проверить доступность»**.

Уведомлений о недоступности сервера пока нет — следите за статусом в панели.

## Удаление сервера

Сервер удаляется из списка: меню → **«Удалить сервер»**.

- Если на сервере есть сервисы (в том числе в корзине), удаление блокируется: перенесите сервисы на другой
  сервер или уберите привязки.
- Владелец и администраторы могут **«Отвязать и удалить сервер»** принудительно. Сервисы останутся в панели
  без сервера, ожидающие развёртывания отменятся, а контейнеры и данные останутся на машине и продолжат
  работать без управления из панели.

<Callout type="warn">
  Удаление сервера в DeployCode не удаляет машину у облачного провайдера и ничего не удаляет на самом
  сервере.
</Callout>
