title: Роли
description: Что участник может делать в организации.
---

**Роль** определяет, какие действия разрешены участнику. Роли смотрят и настраивают в разделе **Роли**.

## Встроенные роли

| Роль | Кратко |
| --- | --- |
| `owner` | Владелец организации. Может всё, в том числе менять настройки организации |
| `admin` | Администратор. Может всё, кроме удаления организации и изменения её настроек |
| `member` | Участник. Не может создавать проекты и сервисы, поэтому без [своей роли](#свои-роли) не видит ни одного проекта |

### Что разрешено

| Что | `owner` | `admin` | `member` |
| --- | --- | --- | --- |
| Настройки организации | ✓ | — | — |
| Участники и приглашения | ✓ | ✓ | — |
| Свои роли | ✓ | ✓ | Только просмотр |
| Создание и удаление проектов | ✓ | ✓ | — |
| Окружения и сервисы: создание и удаление | ✓ | ✓ | Только просмотр |
| Развёртывание и отмена | ✓ | ✓ | ✓ |
| Переменные окружения | ✓ | ✓ | ✓ |
| Домены | ✓ | ✓ | ✓ |
| Логи | ✓ | ✓ | ✓ |
| Серверы, SSH-ключи, реестры образов | ✓ | ✓ | — |
| Git-провайдеры и облачные провайдеры | ✓ | ✓ | — |
| Traefik | ✓ | ✓ | — |
| Корзина | ✓ | ✓ | — |

Пункты меню, на которые у роли нет прав, скрыты. Неактивная кнопка при наведении объясняет, какого права
не хватает.

Видимость проектов зависит от роли: см. [Что видит участник](/docs/access/members#что-видит-участник).

## Свои роли

Если встроенных ролей не хватает, создайте свою: **Роли → «Создать роль»**.

- **Название** — латинские буквы, цифры, дефис и подчёркивание. Имена `owner`, `admin` и `member` заняты.
- **Пресет** — быстрый старт: «Наблюдатель», «Разработчик», «Релиз-инженер», «DevOps».
- **Права** — отметьте, какие действия разрешены для каждого раздела: например, для «Участников» —
  просмотр, приглашение, изменение, удаление.

В свою роль нельзя выдать права на настройки организации и на управление ролями. Права раздела
«Участники» — просмотр, приглашение, изменение роли — выдать можно: такая роль сможет приглашать участников и
менять им роли, в том числе назначать `admin`.

Для работы с проектами удобен пресет **«Разработчик»**: он разрешает создавать проекты и сервисы.

Свою роль можно назначить при [приглашении](/docs/access/invitations) или сменить участнику позже.
Переименование роли применяется ко всем участникам с ней. Удалить роль можно, только когда она никому не
назначена.

## Владелец

У организации ровно один владелец. Его роль нельзя изменить, и её нельзя назначить другому участнику.
