---
title: Роли
description: Что участник может делать в организации и в отдельных проектах.
---

**Роль** определяет, какие действия разрешены участнику. Где он может их выполнять, задают
[проекты](/docs/access/members#роль-и-проекты), выданные ему отдельно: сама роль проектов не даёт. В
выданном проекте можно добавить [роль в проекте](#роль-в-проекте) — она расширяет права только там.

Роли смотрят и настраивают в разделе **Организация → Команда**, на вкладке **«Роли»**. Вкладку видят только
владелец и администраторы. В списке две группы: **«Системные»** и **«Свои»**.

## Системные роли

| Роль | Кратко |
| --- | --- |
| Владелец (`owner`) | Всё, включая передачу и удаление организации |
| Администратор (`admin`) | Всё в организации и во всех проектах, приглашения |
| Участник (`member`) | Развёртывания, переменные сервисов и новые домены в выданных проектах. Не создаёт проекты и сервисы и не управляет инфраструктурой |

Владелец и администраторы работают во всех проектах. Остальным ролям проекты выдают отдельно, см.
[Что видит участник](/docs/access/members#что-видит-участник).

### Что разрешено

| Что | Владелец | Администратор | Участник |
| --- | --- | --- | --- |
| Профиль организации, передача владения, удаление | ✓ | — | — |
| Команда: приглашения, роли и проекты участников, исключение | ✓ | ✓ | — |
| Роли | ✓ | ✓ | — |
| Журнал аудита: просмотр, срок хранения | ✓ | ✓ | — |
| Ассистент: переключатели в настройках организации | ✓ | ✓ | — |
| Участники проекта: добавление, роль в проекте | ✓ | ✓ | — |
| Создание и удаление проектов | ✓ | ✓ | — |
| Окружения и сервисы: создание и удаление | ✓ | ✓ | Только просмотр |
| Настройки сервиса: источник, сборка, тома, порты | ✓ | ✓ | — |
| Развёртывание и отмена | ✓ | ✓ | ✓ |
| Резервные копии: восстановление и расписание | ✓ | ✓ | — |
| Переменные сервиса | ✓ | ✓ | ✓ |
| Переменные проекта и окружения | ✓ | ✓ | Только просмотр |
| Домены: добавление | ✓ | ✓ | ✓ |
| Домены: удаление | ✓ | ✓ | — |
| Логи | ✓ | ✓ | ✓ |
| Серверы, SSH-ключи, реестры образов | ✓ | ✓ | — |
| Терминал сервера, консоль контейнера | ✓ | ✓ | — |
| Git-провайдеры и облачные провайдеры | ✓ | ✓ | — |
| Корзина | ✓ | ✓ | — |

Создать резервную копию сейчас, остановить и запустить приложение для снимка можно с правом на запуск
развёртываний. Восстановление и расписание — отдельные права: восстановление заменяет данные старой
копией, а расписание может выключить копирование.

[Ассистент](/docs/observability/assistant) прав не добавляет: он читает и готовит к запуску только то, что
разрешено роли участника, который с ним говорит. Пользоваться им может любой участник организации, где
ассистент включён.

«Участник» добавляет домены, но не удаляет их: снять адрес с работающего сервиса может только тот, кто
может удалить сервис.

Общие переменные проекта и окружения роль «Участник» только читает. Значение общего
[секрета](/docs/deployments/variables#секреты) видят только роли, которые могут менять переменные на его
уровне. Остальные видят, что секрет задан, но не его значение.

Пункты меню, на которые у роли нет прав, скрыты. Неактивная кнопка при наведении объясняет, какого права
не хватает. Если действие всё же отклонено, панель назовёт причину:

| Сообщение | Что значит |
| --- | --- |
| «Ваша роль не позволяет это действие» | Этого права нет ни в роли в организации, ни в роли в проекте |
| «У вас нет доступа к этому проекту» | Проект, к которому относится объект, вам не выдан |
| «Это доступно только владельцу и администраторам организации» | Действие не выдаётся своим ролям |
| «Вы не состоите в этой организации» | Вас исключили из организации или вы из неё вышли |

Права системной роли не меняются. На её странице есть кнопка **«Дублировать»**: она создаёт свою роль с
тем же набором прав.

### Терминал и консоль контейнера

Это отдельные права, потому что оба дают root-доступ:

- **«Серверы → Терминал»** открывает консоль сервера: в ней доступны все сервисы на нём, включая
  сервисы других проектов. Право подключать серверы терминал не даёт. Без этого права вкладки
  [«Терминал»](/docs/observability/logs#терминал-сервера) на странице сервера нет.
- **«Сервисы → Консоль контейнера»** открывает shell внутри запущенного контейнера одного сервиса. В
  панели такой консоли пока нет.

Каждое открытие терминала записывается в [журнал аудита](/docs/access/audit).

## Свои роли

Если системных ролей не хватает, создайте свою: кнопка **«Создать роль»** на вкладке «Роли» или
**«Дублировать»** у существующей роли.

- **«Основа»** — с чего начать: **«Пустая»** или **«На основе „…“»** любой роли. Права основы
  копируются, кроме тех, что своим ролям недоступны. Что именно убрано, панель напишет под полем.
- **«Название»** — как роль будет видна в команде, например «Тимлид». До 50 символов. Названия системных
  ролей заняты.
- **«Описание»** — для кого роль и что с ней можно.
- **«Права»** — таблица: разделы по группам («Организация», «Приложения», «Переменные», «Инфраструктура»,
  «Интеграции») и действия — «Просмотр», «Создание», «Изменение», «Удаление» и другие, например «Запуск»
  развёртываний или «Восстановление» резервных копий.

Нажмите **«Создать роль»**.

У сервисов «Создание» только добавляет новые сервисы. Менять источник, сборку, тома, порты и токен
развёртывания у существующих позволяет «Изменение». Свои роли, у которых было «Создание», получили
«Изменение» автоматически.

Своя роль не может управлять организацией, ролями и командой: приглашать людей, менять им роли в
организации, исключать из команды. Иначе роль могла бы пригласить или назначить администратора и так
расширить собственные права. Из раздела «Участники» доступен только просмотр списка, а в таблице такие
права отмечены «Только владелец и администраторы».

Людьми внутри проекта своя роль управлять может: право **«Участники проекта → Управление»** позволяет
добавлять в проект участников команды и задавать им роль в нём, но не шире собственных прав. См.
[Участники проекта](/docs/access/members#участники-проекта).

Когда в DeployCode появляется новый раздел, своя роль не получает на него прав, пока её не изменят.

Свою роль можно назначить в [приглашении](/docs/access/invitations) или сменить участнику позже.

### Изменение и удаление

В меню своей роли — **«Изменить»**, **«Дублировать»** и **«Удалить»**. Новое название применяется ко всем,
у кого эта роль.

Если роль есть у людей или в приглашениях, при удалении выберите роль им на замену: «Участник» или другую
свою роль. Администратора на замену выбрать нельзя, чтобы удаление роли ни у кого не расширило права.
Удаление нельзя отменить.

## Роль в проекте

У каждого человека одна роль в организации. В выданном проекте ему можно задать ещё и **роль в
проекте**: она добавляет права к роли в организации, но только в этом проекте.

Например, у человека своя роль «Наблюдатель» с одним просмотром, а в проекте «Магазин» — роль
«Участник». В «Магазине» он развёртывает и меняет переменные сервисов, в остальных выданных проектах
только смотрит.

- Ролью в проекте может быть «Участник» или своя роль. Владельца и администратора выбрать нельзя: они и
  так работают во всех проектах.
- Вариант **«Как в организации»** — роли в проекте нет, действует только роль в организации.
- Роль в проекте только добавляет права и ничего не отнимает.
- Она действует на то, что относится к проекту: окружения, сервисы, развёртывания, резервные копии,
  переменные, домены, логи и участников проекта. Права на серверы, SSH-ключи, провайдеры, реестры,
  команду и роли даёт только роль в организации.

Роль в проекте задают:

- в панели [«Изменить»](/docs/access/members#роль-и-проекты) у участника — рядом с каждым отмеченным
  проектом;
- в окне «Добавить в проект» — одну на всех, кого добавляют;
- на странице [«Участники проекта»](/docs/access/members#участники-проекта) — в строке человека.

Приглашённым роль в проекте не задаётся: проект они получают без неё, роль выбирают после вступления.

## Владелец

У организации ровно один владелец. Его роль не назначается в команде: владение
[передаётся](/docs/structure/organizations#передача-владения) в настройках организации.
