DeployCode получает код из GitHub через **GitHub App**. Персональный токен не нужен: вы сами выбираете,
какие репозитории увидит DeployCode.

<Callout type="info">
  GitLab и SourceCraft видны в интерфейсе, но пока недоступны — интеграция готовится.
</Callout>

## Подключение аккаунта

Подключить GitHub можно в разделе **Git-провайдеры** (кнопка **«Подключить GitHub аккаунт»**) или прямо в
мастере [«Новый проект» или «Новый сервис»](/docs/quick-start#приложение-из-github), на вкладке «GitHub».

1. Если GitHub ещё не привязан к вашему профилю, DeployCode сначала откроет **Аккаунт → Способы входа** с
   подсказкой «Сначала привяжите GitHub к профилю». Нажмите **«Привязать GitHub»**: так DeployCode
   проверит, что выбранный аккаунт GitHub принадлежит вам. После привязки подключение продолжится само —
   откроется установка GitHub App.
2. На GitHub выберите личный аккаунт или организацию GitHub и репозитории, к которым будет доступ.
3. После возврата подключение появится в списке со статусом **«Подключено»**. Из мастера GitHub
   открывается в отдельном окне: после подключения оно закроется само, а аккаунт появится в мастере.

Ссылка подключения одноразовая и действует 10 минут. Если она истекла, начните заново.

Подключать GitHub могут участники с правом на Git-провайдеры. Одна установка GitHub App привязывается только к
одной организации DeployCode.

### App уже установлен

Бывает, что DeployCode App установлен на аккаунт GitHub, но в DeployCode не подключён: например,
подключение отвязали или App установили прямо на GitHub. Тогда страница **Git-провайдеры** и мастер
покажут «DeployCode App уже установлен на …». Нажмите **«Подключить»** — подключение появится сразу, на
GitHub ничего менять не нужно.

Так показываются установки, которыми управляет привязанный к профилю аккаунт GitHub и которые не
подключены ни в одной организации DeployCode.

### Несколько аккаунтов

К организации можно подключить несколько аккаунтов и организаций GitHub. Ещё один аккаунт добавляется
кнопкой **«Подключить GitHub аккаунт»** на странице **Git-провайдеры** или **«Другой аккаунт или
организация»** в мастере. GitHub спросит, на какой аккаунт или организацию установить App, и появится
новое подключение — уже подключённые аккаунты не меняются. При создании сервиса нужный аккаунт выбирается
в поле **«Аккаунт GitHub»**.

## Кто видит подключение

Доступ к подключению показан на странице **Git-провайдеры**, в колонке «Доступ». Новое подключение —
**«Личное»**: его репозитории видят тот, кто подключил аккаунт, а также владельцы и администраторы
организации. Чтобы репозитории видели и разворачивали все участники организации, выберите
в меню **⋯** подключения **«Открыть организации»** — доступ сменится на **«Вся организация»**. Вернуть
обратно — **«Сделать личным»**.

Менять доступ могут тот, кто подключил аккаунт, владелец и администраторы организации. Изменение
записывается в [журнал аудита](/docs/access/audit).

## Доступ к репозиториям

Чтобы открыть DeployCode новые репозитории или закрыть старые:

- на странице **Git-провайдеры** — пункт **«Изменить доступ к репозиториям»** в меню подключения;
- в мастере создания сервиса — **«Нет нужного репозитория? Открыть доступ в GitHub»** под полем
  «Репозиторий». После закрытия окна список репозиториев обновится сам.

### Статусы подключения

| Статус | Что значит |
| --- | --- |
| Подключено | Всё работает |
| Приостановлено | Владелец аккаунта приостановил GitHub App на GitHub — возобновите его там и переподключите |
| Доступ отозван | GitHub App удалён или его доступ отозван — переподключите GitHub |
| Требует внимания | Последний запрос к GitHub не удался, например из-за тайм-аута, сбоя GitHub или лимита запросов. Подключение продолжает работать: первый успешный запрос вернёт статус «Подключено» |

Под статусом, отличным от «Подключено», показана причина. Переподключить аккаунт можно пунктом
**«Переподключить»** в меню подключения, а в мастере — кнопкой **«Переподключить»** под полем
«Репозиторий», когда выбранный аккаунт приостановлен или отозван. GitHub App ставится заново в то же
подключение, второй аккаунт не появляется.

**«Отвязать от DeployCode»** удаляет подключение только в DeployCode — GitHub App останется установленным на
GitHub. Подключить его снова можно одной кнопкой, см. [App уже установлен](#app-уже-установлен).

## Репозиторий и ветка сервиса

Источник кода задаётся при создании сервиса, а меняется в **настройках сервиса**, блок **«Репозиторий»**:

| Поле | Что указать |
| --- | --- |
| Аккаунт GitHub | Подключение, через которое берётся код |
| Репозиторий | Репозиторий с приложением |
| Ветка | Ветка, из которой собирается сервис |
| Путь сборки | Каталог приложения в репозитории, по умолчанию `/` — для монорепозиториев |

При сохранении DeployCode проверяет, что репозиторий доступен и ветка существует.

## Запуск развёртывания

На странице сервиса:

- **«Развернуть»** — собрать последний коммит выбранной ветки и выкатить его вместо текущей версии;
- **«Пересобрать»** — собрать сервис заново.

В истории развёртываний у каждого запуска видно коммит: короткий SHA, первую строку сообщения и автора, а на
вкладке **«Изменения»** — коммиты и файлы, изменившиеся с предыдущего успешного развёртывания.

## Авторазвёртывание

В настройках репозитория есть переключатель **«Авторазвёртывание»**, поле **«Когда развёртывать»** и
**«Отслеживаемые пути»**. У приложений, созданных мастером, авторазвёртывание включено с событием
**«При пуше в ветку»**.

С этим событием каждый пуш в ветку сервиса запускает развёртывание запушенного коммита. Удаление ветки
развёртывание не запускает.

**Отслеживаемые пути** — шаблоны путей в репозитории, например `apps/web/**`. Если они заданы,
развёртывание запустится, только когда пуш изменил хотя бы один подходящий файл. Пустой список — любые
изменения. Это удобно для монорепозитория, где у каждого приложения свой каталог.

<Callout type="info">
  Событие **«При новом теге»** пока не запускает развёртывание. Чтобы выкатывать версии по тегам, нажимайте
  **«Развернуть»** вручную.
</Callout>

## Если доступ к репозиторию потерян

Панель покажет причину в блоке «Репозиторий» и в подсказке к кнопке «Развернуть»:

| Сообщение | Что делать |
| --- | --- |
| Подключение GitHub было удалено из DeployCode | Выберите другой аккаунт в настройках репозитория |
| GitHub App приостановлен владельцем аккаунта | Возобновите App на GitHub и нажмите «Переподключить» |
| GitHub App удалён или его доступ отозван | Переподключите GitHub |
| Нет доступа к подключённому репозиторию | Откройте доступ к репозиторию в GitHub App |

Если сохранить настройки с веткой, которой больше нет, панель покажет ошибку «Выбранная ветка больше не
существует или недоступна». Если список репозиториев не загрузился, под полем «Репозиторий» будет «Не
удалось загрузить репозитории» с причиной и кнопкой **«Повторить»**.

Когда подключение удалено, приостановлено или отозвано, авторазвёртывание затронутых сервисов
выключается. Разовый сбой запроса к GitHub (статус «Требует внимания») авторазвёртывание не выключает.
