DeployCode получает код из GitHub через **GitHub App**. Персональный токен не нужен: вы сами выбираете,
какие репозитории увидит DeployCode.

<Callout type="info">
  GitLab и SourceCraft видны в интерфейсе, но пока недоступны — интеграция готовится.
</Callout>

## Подключение аккаунта

Подключить GitHub можно в разделе **Git провайдеры** (кнопка **«Подключить GitHub аккаунт»**) или прямо в
мастере [первого запуска](/docs/quick-start).

1. Если вы входите в DeployCode не через GitHub, сначала привяжите GitHub к профилю: **Аккаунт → Способы
   входа**. Так DeployCode проверит, что выбранный аккаунт GitHub принадлежит вам.
2. DeployCode откроет GitHub. Выберите личный аккаунт или организацию GitHub и репозитории, к которым будет
   доступ.
3. После возврата подключение появится в списке со статусом **«Подключено»**.

Ссылка подключения одноразовая и действует 10 минут. Если она истекла, начните заново.

Подключать GitHub могут участники с правом на Git-провайдеры. Одна установка GitHub App привязывается только к
одной организации DeployCode.

### Несколько аккаунтов

К организации можно подключить несколько аккаунтов и организаций GitHub. Второй аккаунт добавляйте со
страницы **Git провайдеры**. При создании сервиса нужный аккаунт выбирается в поле **«Аккаунт GitHub»**.

## Доступ к репозиториям

Чтобы открыть DeployCode новые репозитории или закрыть старые:

- на странице **Git провайдеры** — пункт **«Изменить доступ к репозиториям»** в меню подключения;
- в мастере создания сервиса — ссылка **«Настроить доступ GitHub»** рядом с выбором репозитория. После
  закрытия окна список репозиториев обновится сам.

### Статусы подключения

| Статус | Что значит |
| --- | --- |
| Подключено | Всё работает |
| Приостановлено | Владелец аккаунта приостановил GitHub App на GitHub — возобновите его там и переподключите |
| Доступ отозван | GitHub App удалён или его доступ отозван — переподключите GitHub |
| Требует внимания | Проверьте подключение в настройках |

**«Отвязать от DeployCode»** удаляет подключение только в DeployCode — GitHub App останется установленным на
GitHub.

## Репозиторий и ветка сервиса

Источник кода задаётся при создании сервиса, а меняется в **настройках сервиса**, блок **«Репозиторий»**:

| Поле | Что указать |
| --- | --- |
| Аккаунт GitHub | Подключение, через которое берётся код |
| Репозиторий | Репозиторий с приложением |
| Ветка | Ветка, из которой собирается сервис |
| Путь сборки | Каталог приложения в репозитории, по умолчанию `/` — для монорепозиториев |

При сохранении DeployCode проверяет, что репозиторий доступен и ветка существует.

## Запуск развёртывания

На странице сервиса:

- **«Развернуть»** — собрать последний коммит выбранной ветки и выкатить его вместо текущей версии;
- **«Пересобрать»** — собрать сервис заново.

В истории развёртываний у каждого запуска видно коммит: короткий SHA, первую строку сообщения и автора, а на
вкладке **«Изменения»** — коммиты и файлы, изменившиеся с предыдущего успешного развёртывания.

## Авторазвёртывание

<Status value="in-progress" />

В настройках репозитория есть переключатель **«Авторазвёртывание»**, выбор события (**«При пуше в ветку»**
или **«При новом теге»**) и **отслеживаемые пути**. Сейчас пуши в GitHub ещё не запускают сборку
автоматически: выкатывайте новую версию кнопкой **«Развернуть»**.

## Если доступ к репозиторию потерян

Панель покажет причину в блоке «Репозиторий» и в подсказке к кнопке «Развернуть»:

| Сообщение | Что делать |
| --- | --- |
| Подключение GitHub было удалено из DeployCode | Выберите другой аккаунт в настройках репозитория |
| GitHub App приостановлен владельцем аккаунта | Возобновите App на GitHub и нажмите «Переподключить» |
| GitHub App удалён или его доступ отозван | Переподключите GitHub |
| Нет доступа к подключённому репозиторию | Откройте доступ к репозиторию в GitHub App |

Если сохранить настройки с веткой, которой больше нет, панель покажет ошибку «Выбранная ветка больше не
существует или недоступна».

Когда подключение удалено, приостановлено или отозвано, авторазвёртывание затронутых сервисов
выключается.
