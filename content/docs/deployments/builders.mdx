---
title: Сборка (Dockerfile и Railpack)
description: Как DeployCode собирает приложение из репозитория.
---

Приложение из репозитория собирается на вашем сервере одним из двух способов:

- по **Dockerfile**, если он есть в каталоге приложения;
- через [Railpack](https://railpack.com), если Dockerfile нет. Railpack сам определяет язык и фреймворк,
  ставит зависимости и выбирает команду запуска.

По умолчанию используется Railpack **0.35.0**.

## Сборщик

Сборщик выбирается в настройках сервиса, в разделе **«Сборка и запуск»**, полем **«Сборщик»**:

| Сборщик | Как собирается образ |
| --- | --- |
| **Автоматически** | Если в корне каталога сервиса лежит файл `Dockerfile`, образ собирается по нему, иначе — через Railpack |
| **Dockerfile** | Всегда по Dockerfile. Путь к нему задаётся полем **«Путь к Dockerfile»** |
| **Railpack** | Всегда через Railpack, даже если в репозитории есть Dockerfile |

У новых сервисов выбрано **«Автоматически»**. Сервисы, созданные до появления этого режима, собираются
через Railpack, пока вы не смените сборщик.

В режиме «Автоматически» выбор делается при каждой сборке. Dockerfile, добавленный в репозиторий позже,
используется со следующего развёртывания. В журнале сборки видно, какой сборщик сработал: «Найден
Dockerfile в корне сервиса — собираем по нему» или «Dockerfile нет в корне сервиса — собираем через
Railpack».

Файл должен называться ровно `Dockerfile`: `dockerfile` или `Dockerfile.prod` автоматически не
выбираются. Для файла с другим именем или в другом каталоге выберите сборщик **«Dockerfile»** и укажите
путь.

## Сборка по Dockerfile

- **«Путь к Dockerfile»** указывается от каталога сервиса, например `docker/Dockerfile.prod`. По умолчанию —
  `Dockerfile`.
- Контекст сборки — каталог сервиса, где бы ни лежал Dockerfile. Команды `COPY` в нём берут файлы
  относительно этого каталога.
- [Переменные](/docs/deployments/variables) с этапом **«Только сборка»** или **«Сборка и запуск»**
  передаются как аргументы сборки. Чтобы получить переменную в Dockerfile, объявите её через `ARG`;
  остальные Docker пропустит.
- Команды установки, сборки и запуска из раздела «Сборка и запуск» к сборке по Dockerfile не относятся:
  образ собирается и запускается так, как описано в Dockerfile.

<Callout type="warn">
  Значения аргументов сборки могут остаться в истории образа (`docker history`). Не передавайте через
  `ARG` секреты, которые не должны попасть в образ.
</Callout>

Мастер запуска из GitHub видит Dockerfile в каталоге приложения и показывает «Обнаружено: Dockerfile».
Если в последней стадии Dockerfile есть `EXPOSE`, мастер подставит этот порт, см.
[Быстрый старт](/docs/quick-start#настройки).

## Настройки Railpack

Если автоопределение Railpack не подходит, команды можно переопределить в настройках сервиса, в разделе
«Сборка и запуск». Переопределения хранятся в DeployCode и не меняют файлы репозитория. В режиме
«Автоматически» они действуют, только когда в корне сервиса нет Dockerfile.

| Настройка | Что делает |
| --- | --- |
| Команда установки | Заменяет установку зависимостей |
| Команда сборки | Заменяет сборку |
| Результат сборки | **Определить автоматически**, **Веб-сервис** или **Статический сайт** |
| Команда запуска | Заменяет команду запуска (кроме статического сайта) |
| Каталог результата | Каталог с готовыми файлами — обязателен для статического сайта |

Пустое поле означает, что значение определит Railpack. Новые настройки применяются при следующем
развёртывании.

### Результат сборки

- **Определить автоматически** — Railpack сам решает, запускать сервер или отдавать статику.
- **Веб-сервис** — всегда запускать приложение как сервер, даже если Railpack распознал SPA.
- **Статический сайт** — отдавать файлы из **каталога результата** встроенным веб-сервером. Команду
  запуска для статического сайта указать нельзя.

## Путь сборки

Если приложение лежит не в корне репозитория (монорепозиторий), укажите **путь сборки** —
относительный путь к каталогу приложения. От него ищется Dockerfile и отсчитывается «Путь к Dockerfile».

## Переменные Railpack

Railpack настраивается переменными вида `RAILPACK_*` — например, `RAILPACK_NODE_VERSION` или
`RAILPACK_PYTHON_VERSION`. Задайте их как [переменные приложения](/docs/deployments/variables) с этапом
**«Только сборка»** или **«Сборка и запуск»** — с вариантом по умолчанию «Только запуск» Railpack их не
увидит. Переменные для каждого языка — в разделе
[Фреймворки](/docs/frameworks).

## Кеш сборки

Кеш Railpack переиспользуется между развёртываниями. После каждой сборки, в том числе неудачной, его
размер ограничивается 2 ГБ. Заодно с сервера удаляются промежуточные образы без тегов.

Чтобы сбросить кеш, на странице сервера в **«Очистке диска»** выберите **«Кеш сборок»**. Это очищает и кеш
Railpack, и кеш сборок по Dockerfile.
