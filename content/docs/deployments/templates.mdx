**Шаблон** — готовое приложение из одного Docker-образа с заранее настроенными портом, томами и
переменными. Его запуск сводится к выбору сервера: собирать ничего не нужно, образ скачивается на сервер.

## Запуск шаблона

<Steps>
<Step>

### Выберите шаблон

Откройте мастер **«Новый проект»** или **«Новый сервис»**, вкладка **«Шаблоны»**. Каталог можно искать по
названию и описанию и фильтровать по категориям. Шаблон с собственной базой отмечен **«+ PostgreSQL»**.

Шаблон можно открыть и быстрее: в окне [«Что создать?»](/docs/structure/services#окно-что-создать)
начните вводить его название, например `n8n`, и нажмите Enter.

На странице шаблона перечислено, что будет настроено: образ, адрес на `deploycode.app`, тома, база
PostgreSQL и секреты, которые сгенерирует DeployCode. У [ИИ-моделей](#ии-модели) там же указано, сколько
памяти нужно серверу. Ниже — ссылка на документацию приложения.

</Step>
<Step>

### Выберите сервер

Шаг **«Сервер»** такой же, как в остальных вкладках мастера, см.
[Быстрый старт](/docs/quick-start#сервер).

</Step>
<Step>

### Запустите

Проверьте **«Название сервиса»**: по умолчанию это идентификатор шаблона, например `uptime-kuma`. В новом
проекте есть ещё поле **«Название проекта»**: если оставить его пустым, проект назовётся как шаблон.

Нажмите **«Создать и запустить»**. DeployCode создаст сервис, его тома, переменные и домен, запустит
развёртывание и сразу откроет страницу сервиса. Как войти в приложение, подскажет блок
[«Вход»](#вход-в-приложение) на этой странице.

</Step>
</Steps>

## Что настраивает шаблон

| Шаблон | Тома | Переменные |
| --- | --- | --- |
| Open WebUI + Ollama | `/app/backend/data`, `/root/.ollama` | `WEBUI_SECRET_KEY` — секрет |
| Ollama | `/root/.ollama` | — |
| LocalAI | `/models` | `LOCALAI_API_KEY` — секрет, ключ API |
| Uptime Kuma | `/app/data` | — |
| n8n | `/home/node/.n8n` | `N8N_ENCRYPTION_KEY` — секрет |
| Umami | — | `DATABASE_URL` — ссылка на свою базу, `APP_SECRET` — секрет |
| Metabase | `/metabase-data` | `MB_DB_FILE=/metabase-data/metabase.db` |
| Gitea | `/data` | — |
| code-server | `/home/coder` | `PASSWORD` — секрет, пароль для входа |
| Vaultwarden | `/data` | — |
| Excalidraw | — | — |
| IT-Tools | — | — |
| MinIO | `/data` | `MINIO_ROOT_USER=admin`, `MINIO_ROOT_PASSWORD` — секрет |
| Meilisearch | `/meili_data` | `MEILI_ENV=production`, `MEILI_MASTER_KEY` — секрет |
| Valkey | `/data` | `VALKEY_PASSWORD` — секрет |

Каждый путь становится [именованным томом](/docs/deployments/volumes): данные в нём переживают
перезапуск и новые развёртывания.

### Секреты

Секреты генерирует сервер DeployCode при запуске шаблона и сохраняет как
[переменные типа «Секрет»](/docs/deployments/variables#секреты). Пароль для входа, например `PASSWORD` у
code-server или `MINIO_ROOT_PASSWORD` у MinIO, показан в блоке [«Вход»](#вход-в-приложение) на странице
сервиса и в переменных сервиса — кнопкой **«Показать значение»**.

### Своя база PostgreSQL

Umami запускается вместе со своей базой PostgreSQL 17 в том же окружении. База называется
`<имя сервиса>-db`, имя базы и пользователь — `umami`, пароль генерируется. Приложение получает строку
подключения через [ссылку на сервис](/docs/deployments/variables#ссылки-на-сервисы) по внутренней сети,
поэтому пароль никуда не копируется.

Сначала запускается база, затем приложение. Мастер не ждёт базу: страница сервиса открывается сразу и
показывает, что происходит:

| Сообщение | Что значит |
| --- | --- |
| «Запускаем базу … Приложение развернётся следом» | База ещё запускается, обычно это пара минут |
| «База … запущена — ставим приложение в очередь развёртывания» | Через несколько секунд начнётся развёртывание приложения |
| «База … не запустилась, поэтому приложение не развёрнуто» | Откройте базу по ссылке, посмотрите причину и разверните её, затем — сервис |

### Сервисы без веб-интерфейса

У Valkey и Ollama нет порта для браузера, поэтому домен им не выдаётся. Они доступны другим сервисам по
внутренней сети: Valkey — на порту 6379 с паролем из переменной `VALKEY_PASSWORD`, Ollama — на порту 11434.
У API Ollama нет пароля, поэтому наружу он не открыт.

У MinIO адрес на `deploycode.app` ведёт в веб-консоль на порту 9001. S3 API на порту 9000 доступен только
по внутренней сети.

### Подключение из приложения

Адрес, пароль или ключ API Valkey, Meilisearch, MinIO, Ollama и LocalAI не нужно копировать в приложение
вручную. Добавьте приложению переменную типа
[«Ссылка на сервис»](/docs/deployments/variables#ссылки-на-сервисы) и выберите сервис и значение, например
адрес подключения Valkey в `REDIS_URL`. Значение подставится при развёртывании. Приложение и сервис должны
быть в одном окружении, на одном сервере и в общей сети.

Valkey можно создать и вместе с приложением в мастере GitHub — галочкой «Создать Valkey», см.
[База данных и Valkey](/docs/quick-start#база-данных-и-valkey).

### ИИ-модели

Шаблоны категории **«ИИ-модели»** запускают открытые языковые модели на вашем сервере. Модели работают на
его процессоре, поэтому серверу нужно от 8 ГБ памяти: в каталоге такие шаблоны отмечены «от 8 ГБ RAM».
Мастер не проверяет память сервера, поэтому выбирайте его сами, см. [Требования](/docs/servers/requirements).

Модели в образ не входят, их нужно скачать после запуска:

- **Open WebUI + Ollama** — в веб-интерфейсе: **«Настройки → Модели»**, например `qwen2.5:3b`. Ollama
  встроен в образ, поэтому интерфейс и модели работают в одном контейнере;
- **Ollama** — запросом `POST /api/pull` из другого сервиса, например с телом `{"model": "qwen2.5:3b"}`;
- **LocalAI** — из галереи в веб-интерфейсе.

Скачанные модели хранятся на томах и переживают новые развёртывания.

## Вход в приложение

На странице сервиса из шаблона есть блок **«Вход»**: как войти в приложение после запуска. Если учётные
данные сгенерировал DeployCode, они показаны там же, их можно открыть и скопировать. Значения видят те же
участники, кому доступны переменные сервиса.

| Шаблон | Как войти |
| --- | --- |
| Open WebUI + Ollama | Первый зарегистрированный пользователь становится администратором, после этого регистрация закрывается |
| Ollama | Через API по внутренней сети, без пароля |
| LocalAI | Клиенты OpenAI работают как есть: укажите адрес сервиса и ключ `LOCALAI_API_KEY` |
| Uptime Kuma | При первом входе приложение попросит создать администратора |
| n8n | При первом входе приложение попросит создать владельца |
| Umami | `admin` / `umami`. Смените пароль сразу после входа |
| Metabase | При первом входе приложение проведёт через настройку и создание администратора |
| Gitea | При первом входе откроется установка; первый зарегистрированный пользователь станет администратором |
| Vaultwarden | Создайте аккаунт на странице входа. Регистрация открыта всем, кто знает адрес: создав свой аккаунт, закройте её переменной `SIGNUPS_ALLOWED=false` |
| MinIO | Логин и пароль консоли — `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD` |
| Meilisearch | Клиенты обращаются к API с мастер-ключом `MEILI_MASTER_KEY` |
| Valkey | Пароль `VALKEY_PASSWORD` для подключения по внутренней сети |
| code-server | Пароль `PASSWORD` |

У Excalidraw и IT-Tools входа нет.

## Версия приложения

При запуске скачивается последняя версия образа под тегом из каталога: для тега `latest` — последняя
версия приложения, для закреплённой линии (`uptime-kuma:1`, `gitea:1.22`, `meilisearch:v1.11`,
`valkey:8`) — последняя версия внутри неё. Точная версия образа (digest) записывается в историю
развёртываний.

Чтобы обновить приложение, нажмите **«Развернуть»** на странице сервиса: тег скачается заново, и сервис
перейдёт на последнюю версию под ним. Другой тег, например следующая линия Gitea, указывается в настройках
сервиса, в блоке **«Образ»**. Перед сменой линии прочитайте заметки о выпуске приложения: данные в томах
остаются прежними, и новой версии может понадобиться их миграция.

Сервис из шаблона — обычный сервис из Docker-образа, см.
[Обновление образа](/docs/deployments/docker-image#обновление-образа).

## Чего нет в каталоге

Многоконтейнерные приложения вроде Supabase и PostHog требуют Compose. Вкладка **«Compose»** в мастере
пока помечена «скоро». Приложение из одного образа можно запустить на вкладке
[«Docker-образ»](/docs/deployments/docker-image).
