**Шаблон** — готовое приложение из одного Docker-образа с заранее настроенными портом, томами и
переменными. Его запуск сводится к выбору сервера: собирать ничего не нужно, образ скачивается на сервер.

## Запуск шаблона

<Steps>
<Step>

### Выберите шаблон

Откройте мастер **«Новый проект»** или **«Новый сервис»**, вкладка **«Шаблоны»**. Каталог можно искать по
названию и описанию и фильтровать по категориям. Шаблон с собственной базой отмечен **«+ PostgreSQL»**.

Шаблон можно открыть и быстрее: в окне [«Что создать?»](/docs/structure/services#окно-что-создать)
начните вводить его название, например `n8n`, и нажмите Enter.

На странице шаблона перечислено, что будет настроено: образ, адрес на `deploycode.app`, тома, база
PostgreSQL и секреты, которые сгенерирует DeployCode. Там же ссылка на документацию приложения.

</Step>
<Step>

### Выберите сервер

Шаг **«Сервер»** такой же, как в остальных вкладках мастера, см.
[Быстрый старт](/docs/quick-start#сервер).

</Step>
<Step>

### Запустите

Проверьте **«Название сервиса»**: по умолчанию это идентификатор шаблона, например `uptime-kuma`. В новом
проекте есть ещё поле **«Название проекта»**: если оставить его пустым, проект назовётся как шаблон.

Нажмите **«Создать и запустить»**. DeployCode создаст сервис, его тома, переменные и домен, запустит
развёртывание и откроет страницу сервиса.

</Step>
</Steps>

## Что настраивает шаблон

| Шаблон | Тома | Переменные |
| --- | --- | --- |
| Uptime Kuma | `/app/data` | — |
| n8n | `/home/node/.n8n` | `N8N_ENCRYPTION_KEY` — секрет |
| Umami | — | `DATABASE_URL` — ссылка на свою базу, `APP_SECRET` — секрет |
| Metabase | `/metabase-data` | `MB_DB_FILE=/metabase-data/metabase.db` |
| Gitea | `/data` | — |
| code-server | `/home/coder` | `PASSWORD` — секрет, пароль для входа |
| Vaultwarden | `/data` | — |
| Excalidraw | — | — |
| IT-Tools | — | — |
| MinIO | `/data` | `MINIO_ROOT_USER=admin`, `MINIO_ROOT_PASSWORD` — секрет |
| Meilisearch | `/meili_data` | `MEILI_ENV=production`, `MEILI_MASTER_KEY` — секрет |
| Valkey | `/data` | `VALKEY_PASSWORD` — секрет |

Каждый путь становится [именованным томом](/docs/deployments/volumes): данные в нём переживают
перезапуск и новые развёртывания.

### Секреты

Секреты генерирует сервер DeployCode при запуске шаблона и сохраняет как
[переменные типа «Секрет»](/docs/deployments/variables#секреты). Пароль для входа, например `PASSWORD` у
code-server или `MINIO_ROOT_PASSWORD` у MinIO, можно посмотреть в переменных сервиса кнопкой
**«Показать значение»**.

### Своя база PostgreSQL

Umami запускается вместе со своей базой PostgreSQL 17 в том же окружении. База называется
`<имя сервиса>-db`, имя базы и пользователь — `umami`, пароль генерируется. Приложение получает строку
подключения через [ссылку на сервис](/docs/deployments/variables#ссылки-на-сервисы) по внутренней сети,
поэтому пароль никуда не копируется. Сначала запускается база, затем приложение.

### Сервисы без веб-интерфейса

У Valkey нет порта для браузера, поэтому домен ему не выдаётся. Он доступен другим сервисам по внутренней
сети. Пароль лежит в переменной `VALKEY_PASSWORD`.

У MinIO адрес на `deploycode.app` ведёт в веб-консоль на порту 9001. S3 API на порту 9000 доступен только
по внутренней сети.

## Версия приложения

При запуске скачивается последняя версия образа под тегом из каталога: для тега `latest` — последняя
версия приложения, для закреплённой линии (`uptime-kuma:1`, `gitea:1.22`, `meilisearch:v1.11`,
`valkey:8`) — последняя версия внутри неё. Точная версия образа (digest) записывается в историю
развёртываний.

Чтобы обновить приложение, нажмите **«Развернуть»** на странице сервиса: тег скачается заново, и сервис
перейдёт на последнюю версию под ним. Другой тег, например следующая линия Gitea, указывается в настройках
сервиса, в блоке **«Образ»**. Перед сменой линии прочитайте заметки о выпуске приложения: данные в томах
остаются прежними, и новой версии может понадобиться их миграция.

Сервис из шаблона — обычный сервис из Docker-образа, см.
[Обновление образа](/docs/deployments/docker-image#обновление-образа).

## Чего нет в каталоге

Многоконтейнерные приложения вроде Supabase и PostHog требуют Compose. Вкладка **«Compose»** в мастере
пока помечена «скоро». Приложение из одного образа можно запустить на вкладке
[«Docker-образ»](/docs/deployments/docker-image).
