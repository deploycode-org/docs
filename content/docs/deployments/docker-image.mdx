Сервис можно запустить из готового Docker-образа: например, собранного в вашем CI или опубликованного
автором приложения. DeployCode ничего не собирает — образ скачивается на сервер при развёртывании.

## Запуск образа

Откройте мастер **«Новый проект»** или **«Новый сервис»**, вкладка **«Docker-образ»**. Сначала выберите
[сервер](/docs/quick-start#сервер), затем заполните шаг **«Образ и запуск»**:

| Поле | Что указать |
| --- | --- |
| **Образ** | Образ из Docker Hub, GHCR или другого реестра с тегом или digest: `nginx:1.27`, `ghcr.io/acme/web:1.2`, `registry.example.com:5000/team/app:1.0`, `repo@sha256:…`. Только строчные буквы |
| **Приватный реестр** | Включите, если для скачивания образа нужен логин, см. [ниже](#приватный-реестр) |
| **Название сервиса** | Подставляется из имени образа: для `ghcr.io/acme/web:1.2` — `web`. До 63 символов |
| **Порт веб-интерфейса** | Порт, который приложение слушает внутри контейнера, по умолчанию `80`. На него поведёт адрес на `deploycode.app` |
| **Переменные** | Необязательно. По одной на строку в формате `KEY=value`, пустые строки и строки с `#` в начале пропускаются. До 100 переменных |
| **Тома** | Необязательно. Пути внутри контейнера по одному на строку, например `/data`. Каждый путь станет [именованным томом](/docs/deployments/volumes). До 10 путей |
| **Название проекта** | Только в новом проекте. Если оставить пустым, проект назовётся как сервис |

Нажмите **«Создать и запустить»**. DeployCode создаст сервис, запустит развёртывание и откроет страницу
сервиса.

### Приватный реестр

Если образ лежит в приватном реестре — GHCR, GitLab, Yandex Container Registry или закрытом
репозитории Docker Hub, — включите **«Приватный реестр»** и укажите **«Логин»** и **«Пароль или токен»**.
Адрес реестра вводить не нужно: он берётся из имени образа, а образ без адреса реестра скачивается из
Docker Hub. Какой реестр определился, видно под полем «Образ».

Кнопка **«Проверить доступ»** входит в реестр с выбранного сервера так же, как это сделает скачивание
образа. Если всё в порядке, появится «Вход подтверждён», иначе — ошибка реестра. Так неверный токен
обнаружится до запуска, а не после неудачного развёртывания.

Пароль хранится зашифрованным и после сохранения в панели не показывается. Лучше выпустить для DeployCode
отдельный токен, который может только читать пакеты.

### Сервис без веб-интерфейса

Если у приложения нет HTTP-интерфейса, как у воркера или очереди, выключите переключатель **HTTP** рядом с
портом. Домен такому сервису не выдаётся, он доступен только другим сервисам по внутренней сети.

### Переменные

Переменные из мастера сохраняются как обычные значения, а не [секреты](/docs/deployments/variables#секреты):
их видно в панели всем, кому роль разрешает просмотр переменных. Пароли и ключи после запуска можно
сделать секретами: измените переменную и выберите тип **«Секрет»**.

## Как развёртывается образ

DeployCode скачивает образ на сервер по указанному тегу, определяет его точную версию (digest) и
записывает её в историю развёртываний. Если в поле «Образ» указан digest, скачивается ровно эта версия.

[Сборщик](/docs/deployments/builders) и [сервер сборки](/docs/deployments/build-server) для образа не
используются. Поэтому на странице сервиса нет кнопки **«Пересобрать»**, а журнал развёртывания
открывается кнопкой **«Логи развёртывания»**. В блоке **«Источник»** на
[обзоре сервиса](/docs/structure/services#текущая-версия) видны образ и начало digest текущей версии.

## Обновление образа

Кнопка **«Развернуть»** на странице сервиса скачивает образ заново. Если под тем же тегом в реестре
появилась новая версия, например у `latest`, сервис перейдёт на неё.

Чтобы перейти на другой тег или сменить образ, откройте настройки сервиса, блок **«Образ»**. В нём видно,
какой образ запускается, из какого реестра и с каким доступом: **«Публичный образ»** или
**«Приватный, вход как …»**. Кнопка **«Изменить»** открывает панель с полями «Образ», «Приватный реестр»,
«Логин» и «Пароль или токен». Изменения применятся при следующем развёртывании, поэтому после сохранения
нажмите «Развернуть».

Если меняется только тег, пароль вводить заново не нужно: оставьте поле пустым, и сохранённый пароль
останется. Для нового логина пароль нужно указать. Если выключить «Приватный реестр», логин и пароль
удаляются. Кнопка «Проверить доступ» есть и здесь: пока логин прежний, она проверяет сохранённый пароль.

Менять образ могут участники, чья [роль](/docs/access/roles) разрешает изменять сервисы.

## Автообновление

Сервис может развёртываться сам, когда в реестр загружают новую версию его образа. Реестр сообщает об этом
через вебхук — адрес, который выдаёт DeployCode.

1. В настройках сервиса, в блоке **«Автообновление»**, включите переключатель. У нового сервиса он
   выключен.
2. Скопируйте **«Адрес вебхука»**.
3. Добавьте адрес в реестр. Панель показывает инструкцию только для реестра вашего образа:
   - **Docker Hub** — репозиторий образа → **Webhooks** → вставьте адрес;
   - **GHCR** — **Settings** репозитория или организации на GitHub → **Webhooks**: адрес, Content type
     `application/json`, событие **Packages**;
   - **другой реестр** — если он умеет отправлять вебхуки, укажите адрес в его настройках;
   - **из CI** — после публикации образа выполните `curl -X POST <адрес>`. Подходит для любого реестра.

Развёртывание запускается, только когда загружен тот же образ с тем же тегом, что у сервиса. Если тег не
указан, это `latest`. О загрузке других тегов и образов реестр тоже сообщает, но такие события
пропускаются. Пропускаются и события, которые не относятся к образам, например пуш в репозиторий GitHub
или GitLab. Запрос без события реестра или git-хостинга, например `curl` из CI, разворачивает образ
сервиса так же, как кнопка «Развернуть».

Пропущенный запрос, в том числе при выключенном автообновлении, вебхук не считает ошибкой: реестр получает
ответ `200`, а причина пропуска есть в тексте ответа. Поэтому в журнале доставок реестра нет ошибок.

Автообновление не работает с образом, закреплённым по digest: новая загрузка его не меняет. Чтобы
обновляться автоматически, укажите в образе тег.

Вебхук настраивается в том реестре, куда публикуется образ, поэтому автообновление подходит для ваших
собственных образов. Для чужого образа, например из [шаблона](/docs/deployments/templates), нажимайте
«Развернуть».

### Адрес вебхука

Адрес сам запускает развёртывание, поэтому храните его как пароль. Его видят только участники с правом
запускать развёртывания, а включать автообновление и выпускать новый адрес могут участники, у которых есть
ещё и право изменять сервисы.

Если адрес мог попасть к посторонним, нажмите **«Выпустить новый адрес»**. Старый адрес сразу перестанет
работать, замените его в реестре и CI.

## Ограничения

Источник сервиса после создания не меняется: сервис из образа нельзя переключить на репозиторий, и
наоборот. Чтобы собирать приложение из кода, создайте новый сервис на вкладке «GitHub».

## Приложения из GitLab и SourceCraft

Вкладки **GitLab** и **SourceCraft** в мастере пока помечены «скоро». До их появления соберите образ в
CI своего репозитория, опубликуйте его в реестре и запустите на вкладке «Docker-образ». Чтобы новые версии
выкатывались сами, включите [автообновление](#автообновление) и добавьте в CI вызов вебхука.
