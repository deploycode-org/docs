**Сервис** — всё, что можно развернуть в [окружении](/docs/structure/environments). Сейчас поддерживаются два
вида:

| Вид | Что это |
| --- | --- |
| Приложение | Собирается из [репозитория GitHub](/docs/deployments/github) или запускается из готового [Docker-образа](/docs/deployments/docker-image), в том числе из [шаблона](/docs/deployments/templates) |
| PostgreSQL | База данных на вашем сервере — см. [PostgreSQL](/docs/databases/postgres) |

## Создание сервиса

Сервисы создаются в мастере **«Новый сервис»** с вкладками **«Шаблоны»**, **«GitHub»**, **«Docker-образ»** и
**«База данных»**, см. [Быстрый старт](/docs/quick-start#что-запустить). Сервис создаётся в окружении,
выбранном в [области](/docs/structure/scope), а если окружение не выбрано — в окружении проекта по
умолчанию.

Мастер открывается кнопкой **«Новый сервис»** на страницах «Проекты», «Окружения» и «Сервисы», когда в
области выбран проект.

### Окно «Что создать?»

Кнопка **«Создать»** на левой панели или клавиша `C` открывает окно **«Что создать?»**:

| Пункт | Что открывает |
| --- | --- |
| **Шаблон** | Каталог [шаблонов](/docs/deployments/templates) |
| **Приложение из GitHub** | Мастер на вкладке «GitHub» |
| **Docker-образ** | Мастер на вкладке «Docker-образ» |
| **База данных** | Мастер на вкладке «База данных» |
| **Проект** | Мастер [«Новый проект»](/docs/structure/projects#создание-проекта) |
| **Окружение** | Форму нового [окружения](/docs/structure/environments#создание-окружения) |
| **Пригласить в команду** | [Приглашение](/docs/access/invitations) в организацию |
| **Сервер** | [Подключение сервера](/docs/servers/connect) |

Пункты, на которые у вашей роли нет прав, не показываются. Поиск находит пункты и шаблоны по началу слов:
введите `n8n` и нажмите Enter — откроется запуск n8n.

Если в области не выбран проект, после выбора сервиса окно спросит **«В каком проекте?»**. Первым идёт
пункт **«В новом проекте»**: проект с окружением `production` создастся вместе с сервисом. В существующем
проекте сервис создаётся в окружении по умолчанию.

## Страница «Сервисы»

Страница показывает сервисы выбранной области плитками. Нажатие на плитку сужает область, а страница
остаётся той же.

| Область | Что на странице |
| --- | --- |
| Организация | Сервисы, сгруппированные по проектам. На плитке указано окружение |
| Проект | Сервисы, сгруппированные по окружениям |
| Окружение | Группы «Приложения» и «Базы данных» |
| Сервис | [Обзор сервиса](#обзор-сервиса) |

Окружения идут в [порядке конвейера](/docs/structure/environments#порядок-окружений), а внутри группы
первыми — сервисы с ошибкой и те, что разворачиваются. Шапка страницы и лента «Активность» справа общие
для рабочих страниц, см. [Плитки и активность](/docs/structure/scope#плитки-и-активность).

На плитке приложения:

- домен: первый собственный, иначе управляемый, или «Без домена»;
- текущая версия — коммит и время последнего успешного развёртывания, или «Ещё не развёрнут»;
- если последняя попытка идёт или упала — «разворачивается» или «ошибка развёртывания» с коммитом.

На плитке PostgreSQL — версия и последняя [резервная копия](/docs/backups/postgres): например,
«бэкап сегодня 14:30», «бэкапов ещё не было» или «бэкапы не настроены».

### Статус сервиса

Цвет точки на плитке — статус сервиса. Подпись видна при наведении:

| Статус | Что значит |
| --- | --- |
| Развёрнут | Последнее развёртывание прошло успешно |
| Разворачивается | Идёт развёртывание |
| Ошибка развёртывания | Последнее развёртывание завершилось ошибкой |
| Не развёрнут | Приложение ещё не развёртывали (для PostgreSQL — база остановлена или ещё не запускалась) |
| Статус развёртывания неизвестен | Статус последнего развёртывания не получен |
| Развёртывание отменено | Последнее развёртывание отменили |

У проекта и окружения точка показывает худший статус среди их сервисов.

## Обзор сервиса

Если в области выбран сервис, страница «Сервисы» показывает его обзор. На страницах «Проекты» и
«Окружения» выбор сервиса тоже открывает «Сервисы».

В шапке — название сервиса и ссылки **«также в: …»** на сервисы с тем же названием в других окружениях.
Кнопки:

- шестерёнка **«Настройки»** — [настройки приложения](#настройки-приложения);
- **«Пересобрать»** — собрать заново текущий коммит. У сервиса из Docker-образа этой кнопки нет;
- **«Развернуть»** — собрать последний коммит ветки и выкатить его, а у сервиса из
  [Docker-образа](/docs/deployments/docker-image#обновление-образа) — скачать образ заново. См.
  [Жизненный цикл развёртывания](/docs/deployments#как-запустить).

Если развернуть нельзя, кнопка «Развернуть» неактивна, а подсказка при наведении называет причину.

### Текущая версия

Главная карточка показывает, что сейчас работает:

| Блок | Что показывает |
| --- | --- |
| Превью | Скриншот сайта. Нажатие открывает адрес сервиса, см. [Превью](/docs/observability/previews) |
| **Служебный адрес** | [Управляемый домен](/docs/networking/managed-domains) на `deploycode.app` |
| **Домены** | Основной собственный домен, работают ли домены по HTTPS, и ссылка **«Все домены»** |
| **Статус** | Что сейчас запущено в Docker, см. [ниже](#статус-в-docker) |
| **Развёрнуто** | Когда прошло последнее успешное развёртывание и сколько длилась сборка, а у сервиса из Docker-образа — развёртывание. Если после него была неудачная или ещё идущая попытка — **«Последняя попытка»** с её статусом |
| **Источник** | Ветка, репозиторий и коммит текущей версии. У сервиса из Docker-образа — образ и начало digest текущей версии, полный digest — в подсказке |

Внизу карточки написано, как обновляется сервис: «Чтобы обновить сервис, отправьте коммит в ветку …»
при включённом [авторазвёртывании](/docs/deployments/github#авторазвёртывание) или «Автодеплой выключен».
У сервиса из Docker-образа — «Обновляется сам, когда в реестр пушат тег этого образа» при включённом
[автообновлении](/docs/deployments/docker-image#автообновление) или подсказка сменить тег в настройках и
развернуть. Там же кнопки **«Логи сборки»** (у сервиса из образа — **«Логи развёртывания»**) и
**«Все развёртывания»**.

Под карточкой:

- **«Сервер»** — где работает сервис. Если сервер не отвечает, видно, когда он отвечал в последний раз;
- **«Контейнер»** — имя сервиса в Docker и число запущенных реплик;
- **«Последние развёртывания»** — пять последних развёртываний, журнал открывается прямо в строке;
- **«Вход»** — у сервиса из [шаблона](/docs/deployments/templates#вход-в-приложение): как войти в
  приложение и сгенерированные учётные данные.

Пока у шаблона со своей базой идёт первый запуск, над карточкой видно, что база ещё запускается и когда
приложение встаёт в очередь развёртывания, см. [Своя база PostgreSQL](/docs/deployments/templates#своя-база-postgresql).

### Статус в Docker

| Статус | Что значит |
| --- | --- |
| Сервис запущен | Все реплики работают |
| Не все реплики запущены | Docker ещё запускает часть реплик |
| Не отвечает на порту … | Реплики работают, но приложение слушает другой порт или только `127.0.0.1`, а адрес ведёт на этот порт. Домен ответит ошибкой 502 |
| Не открыло ни одного порта | Контейнер работает, но приложение не слушает ни одного порта, хотя у сервиса есть адрес. Фоновому процессу без веб-интерфейса адрес не нужен |
| Сервис остановлен | В Docker задано 0 реплик |
| Собирается | Первое развёртывание ещё идёт: сервис появится в Docker, когда закончится сборка. У сервиса из Docker-образа — «Разворачивается», пока сервер скачивает образ |
| Сборка не удалась | Сервиса в Docker нет, а последнее развёртывание завершилось ошибкой. Причина — в логах развёртывания. У сервиса из Docker-образа — «Развёртывание не удалось» |
| Сервис не найден на сервере | На выбранном сервере такого сервиса нет |
| Состояние неизвестно | Панель не смогла проверить сервер, последняя проверка старше минуты или у сервиса не выбран сервер |

Под статусом — число запущенных реплик и время последней проверки.

Порт панель проверяет у работающего сервиса с адресом, через минуту после запуска контейнера: смотрит, какие
порты приложение открыло внутри контейнера. Если оно слушает другой порт, рядом со статусом появится кнопка
**«Указать порт …»**: она переводит адреса сервиса на этот порт. Кнопка видна ролям с правом на домены.
Почему порт обычно совпадает сам, описано в разделе [Порт](/docs/frameworks#порт--главное-что-нужно-проверить).

Статус в Docker не зависит от результата последнего развёртывания: если новое развёртывание упало,
предыдущая версия может продолжать работать.

### Настройки приложения

Настройки открываются шестерёнкой в шапке обзора.

| Раздел | Что настраивается |
| --- | --- |
| Репозиторий | [Аккаунт GitHub, репозиторий, ветка, путь сборки](/docs/deployments/github#репозиторий-и-ветка-сервиса) |
| Образ | Вместо «Репозитория» у сервиса из Docker-образа: [образ, реестр и вход в него](/docs/deployments/docker-image#обновление-образа) |
| Автообновление | Только у сервиса из Docker-образа: [развёртывание по вебхуку реестра](/docs/deployments/docker-image#автообновление) |
| Сборка и запуск | [Команды и результат сборки](/docs/deployments/builders). У сервиса из Docker-образа раздела нет |
| Сервер сборки | [Где собирать](/docs/deployments/build-server) и [в какой реестр публиковать образы](/docs/deployments/registry). У сервиса из Docker-образа раздела нет |
| Именованные тома | [Постоянные данные](/docs/deployments/volumes) |
| Опасная зона | **«Переместить в корзину»**: сервис останавливается на сервере, тома и файлы сохраняются. Через 7 дней DeployCode удаляет его с сервера вместе с томами, см. [Корзина](/docs/structure/trash) |

Переменные приложения задаются в [панели сервиса на «Архитектуре»](/docs/structure/architecture#панель-сервиса),
домены — в разделе [«Домены»](/docs/networking).

<Callout type="info">
  Число реплик и лимиты CPU и памяти для приложений в панели пока не настраиваются. Для PostgreSQL лимиты
  есть в «Расширенных настройках».
</Callout>
