## Как Railpack собирает Next.js

1. Определяет Node.js по `package.json` и менеджер пакетов — по полю `packageManager` или lock-файлу.
2. Ставит зависимости и выполняет скрипт `build` (`next build`).
3. Запускает скрипт `start` (`next start`).

Каталог `.next/cache` сохраняется между сборками в [кеше сборки](/docs/deployments/builders#кеш-сборки)
сервера. Сборку Next.js 16 он почти не ускоряет: Turbopack не пишет туда кеш компиляции. Зато в нём лежит
ключ, из которого Next.js получает id Server Actions, см. [ISR и Server Actions](#isr-и-server-actions).

## Порт

`next start` слушает переменную `PORT`, а без неё — **3000**. DeployCode передаёт в `PORT` порт домена, так
что дополнительно ничего настраивать не нужно.

## Переменные окружения

- Переменные `NEXT_PUBLIC_*` встраиваются в клиентский код **при сборке**. Отметьте у них
  «Использовать при» → **«Сборка и запуск»**: по умолчанию новые переменные доступны только при запуске.
  После изменения таких переменных нужно новое развёртывание.
- Остальные переменные читаются на сервере при запуске.

См. [Переменные окружения](/docs/deployments/variables).

## Что работает

Проверено на Next.js 16 со сборкой Railpack: Route Handlers, Server Actions, `proxy.ts` (бывший
middleware), ISR с `revalidate` и `revalidatePath`, `next/image` (sharp уже есть в образе Railpack),
стриминг и Suspense — Traefik отдаёт ответ по частям, не дожидаясь конца.

## ISR и Server Actions

- Новый контейнер начинает с кеша ISR, сделанного при сборке: страницы, перерисованные в старом контейнере,
  после развёртывания перерисуются заново. У каждой реплики свой кеш.
- Пока `.next/cache` на месте, id Server Actions между развёртываниями не меняются, и вкладки, открытые до
  развёртывания, продолжают работать. Кеш удаляют кнопки **«Кеш сборок»** и **«Полная очистка»** на
  странице сервера. Тогда следующая сборка получит новые id, а открытые вкладки покажут ошибку при вызове
  Server Action, пока страницу не перезагрузят. Автоматическая очистка перед сборкой при
  [нехватке места](/docs/servers/requirements#диск) `.next/cache` не удаляет.

## Статический экспорт

Если в `next.config.*` указано `output: 'export'`, Railpack соберёт статический сайт из каталога `out` и
будет отдавать его встроенным веб-сервером. Сервер слушает порт из `PORT`, который передаёт DeployCode.
См. [Статический сайт](/docs/frameworks/static).

## Версия Node.js

Берётся из `engines.node` в `package.json`, `.nvmrc` или `.node-version`; по умолчанию — 22.
Переопределяется переменной `RAILPACK_NODE_VERSION`.

## Частые проблемы

<Accordions>
  <Accordion title="Сборка падает с нехваткой памяти">
    `next build` требователен к памяти, а сборка идёт на том же сервере, где работают приложения.
    Увеличьте память сервера или освободите её на время сборки.
  </Accordion>
  <Accordion title="Сборка падает: не хватило места на диске">
    Сборке Next.js на пике нужно около 4 ГБ свободного места. На диске 10 ГБ рядом с другими сервисами и
    образом работающего сервиса его может не хватить. См.
    [Не хватило места на диске](/docs/troubleshooting/builds#не-хватило-места-на-диске).
  </Accordion>
  <Accordion title="Изменил переменную NEXT_PUBLIC_*, а на сайте старое значение">
    Такие переменные встраиваются при сборке. Проверьте, что у переменной выбран этап «Сборка и запуск», и
    запустите новое развёртывание.
  </Accordion>
</Accordions>
