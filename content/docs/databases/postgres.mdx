## Создание базы

**Новый сервис → PostgreSQL** в нужном окружении. Мастер **«Новая база PostgreSQL»** состоит из трёх
шагов: тип, сервер, настройки.

| Поле | Что указать |
| --- | --- |
| Название сервиса | Как база будет называться в панели |
| Имя базы | Подставляется из названия: латинские буквы, цифры и подчёркивание. Для названия на кириллице — `app` |
| Пользователь | По умолчанию `app` |
| Версия | PostgreSQL 18 (по умолчанию), 17 или 16 |
| Пароль | Оставьте пустым — DeployCode создаст пароль сам. В пароле нельзя использовать пробелы и символы `$ ! ' " \ /` |

Кнопка **«Создать и запустить»** создаёт базу и сразу запускает её. Данные хранятся в отдельном постоянном
Docker-томе на выбранном сервере.

<Callout type="warn">
  Версию PostgreSQL после создания в панели изменить нельзя. Выбирайте версию сразу.
</Callout>

## Подключение из приложения

На странице базы, в разделе **«Подключение»**, есть готовые строки — их можно скопировать.

### Внутри сервера

Для приложения на том же сервере — рекомендуемый вариант, порт наружу не открывается:

```bash
DATABASE_URL=postgresql://app:<пароль>@<имя-сервиса-docker>:5432/<имя-базы>
```

**Имя сервиса Docker** указано в разделе «Подключение». Там же есть вариант с отдельными переменными
`PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`.

Скопируйте строку в [переменные](/docs/deployments/variables) приложения и задеплойте его. Приложение и
база должны работать на одном сервере.

<Callout type="info">
  Удобно один раз сохранить `DATABASE_URL` в переменных окружения, а в приложениях ссылаться на него:
  `DATABASE_URL=${{environment.DATABASE_URL}}`.
</Callout>

### Внешнее подключение

Чтобы подключиться из DBeaver, DataGrip или с другого сервера, откройте внешний порт: блок **«Настройка
внешнего порта»**, поле **«Порт на сервере»**, затем **«Сохранить и применить»**. PostgreSQL перезапустится.
Пустое значение закрывает порт.

<Callout type="warn">
  Открытый порт доступен по публичному IP сервера. Ограничьте входящие подключения файрволом и используйте
  надёжный пароль.
</Callout>

### Пароль

Пароль скрыт: **«Показать»** открывает его, **«Скопировать»** копирует. **«Изменить пароль»** меняет пароль
пользователя прямо в работающей базе — после этого обновите переменные приложений.

## Управление

В шапке страницы базы:

| Кнопка | Что делает |
| --- | --- |
| Резервные копии | Открывает [копии этой базы](/docs/backups/postgres) |
| Редактировать | Название и описание |
| Остановить | Останавливает базу. Данные остаются в томе |
| Запустить / Развернуть снова | Запускает базу или применяет изменённые настройки |

В **«Расширенных настройках»** — лимиты памяти и CPU контейнера и именованные тома. Изменения применяются
после **«Развернуть снова»**. Удаление тома из списка не удаляет сам Docker-том на сервере.

## Логи

Раздел **«Логи PostgreSQL»** — кнопка **«Показать логи»**. Отдельно есть **«Логи развёртывания»** —
вывод Docker при последнем запуске.

## Резервные копии

Автоматические копии по расписанию, ручные копии и восстановление на другой сервер — см.
[Резервные копии PostgreSQL](/docs/backups/postgres).

## Удаление

**«Опасная зона» → «Удалить PostgreSQL»**.

<Callout type="error">
  База удаляется сразу, без [корзины](/docs/structure/trash). Вместе с ней удаляется история её резервных
  копий. Docker-том с данными остаётся на сервере, но не считайте его резервной копией.
</Callout>
