title: Собственные домены

---

**Собственный домен** — домен в зоне, которой управляете вы: поддомен (`app.example.com`) или корневой
домен (`example.com`). DNS-запись создаёте вы у своего регистратора, а DeployCode подсказывает, какую
именно, и проверяет, что она работает.

<Steps>
<Step>

### Добавьте домен

В настройках доменов приложения выберите собственный домен, укажите хост и
[порт контейнера](/docs/networking#настройки-домена).

</Step>
<Step>

### Создайте DNS-запись

Откройте **Настроить DNS** — панель покажет готовую запись для копирования. Имя записи указывается
относительно вашей зоны: `@` для корневого домена, `app` для `app.example.com`.

</Step>
<Step>

### Дождитесь проверки

DeployCode проверяет запись раз в минуту. Когда она начнёт указывать на сервер, статус станет
**Настроен**, а HTTPS включится сам.

</Step>
</Steps>

## Какую запись создать

| Запись | Когда | Значение |
| --- | --- | --- |
| **A** — основной вариант | Всегда | Публичный IP-адрес сервера |
| **CNAME** — альтернатива | Только для поддоменов | Управляемый домен приложения |
| **CNAME `www`** — дополнительно | Для корневого домена | Корневой домен |

A-запись надёжнее: она не зависит от других записей. CNAME перестанет работать, если удалить
управляемый домен приложения, на который она указывает.

<Callout type="warn">
  Удалите лишние A-записи и AAAA-записи хоста, которые указывают на другие адреса. Иначе часть посетителей
  попадёт на другой сервер, а сертификат может не выпуститься.
</Callout>

## Статусы проверки DNS

| Статус | Что значит |
| --- | --- |
| **Не проверен** | Проверка ещё не выполнялась |
| **Ждём DNS** | Запись ещё не видна — обычно это распространение DNS. Проверка повторяется автоматически |
| **Настроен** | Домен указывает только на IP-адрес сервера. HTTPS включается автоматически |
| **Ошибка** | Домен указывает на другой адрес или сразу на несколько. Панель покажет, что исправить |
| **За CDN** | Домен указывает на CDN (например, Cloudflare в режиме прокси). Проверить сервер снаружи нельзя — HTTPS включается вручную |
| **Удаляется** | Домен и его маршрут удаляются с сервера |

## Домен за CDN

Если домен проксируется через CDN, DeployCode видит адрес CDN, а не вашего сервера, поэтому не выпускает
сертификат автоматически. Убедитесь, что origin в CDN указывает на IP-адрес сервера, и включите HTTPS
вручную, если сертификат выпускает не CDN.
