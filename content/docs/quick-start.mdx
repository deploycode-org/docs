Первый сервис запускается в мастере **«Новый проект»**. Проект создаётся вместе с этим сервисом — с
окружением `production` и адресом на `deploycode.app` с HTTPS.

Мастер открывается на странице **«Проекты»** — с неё начинается работа после входа: кнопка
**«Новый проект»** в шапке или **«Создать проект»**, пока проектов нет. Ещё один путь — пункт **«Проект»** в
окне [«Что создать?»](/docs/structure/services#окно-что-создать).

## Что понадобится

- **Сервер**: свой VPS с доступом по SSH под `root` или пользователем с sudo без пароля, либо сервер в
  подключённом облаке — reg.ru Cloud или Yandex Cloud. См. [Требования](/docs/servers/requirements).
- **GitHub** — только для приложения из репозитория. GitLab и SourceCraft пока не поддерживаются.

Справа от каталога шаблонов мастер показывает, что уже подключено: сервер и GitHub. Недостающее можно
подключить прямо по ходу мастера.

## Что запустить

Мастер начинается с выбора вкладки:

| Вкладка | Что запускает |
| --- | --- |
| **Шаблоны** | Готовое приложение из [каталога](/docs/deployments/templates): Open WebUI, Uptime Kuma, n8n и ещё 12. Образ, тома и секреты уже настроены |
| **GitHub** | Ваше приложение из репозитория: DeployCode соберёт его на сервере |
| **Docker-образ** | Любой [образ](/docs/deployments/docker-image) из Docker Hub, GHCR или другого реестра, в том числе приватного |
| **База данных** | [PostgreSQL](/docs/databases/postgres) на вашем сервере |

Вкладки **GitLab**, **SourceCraft** и **Compose** помечены «скоро». Приложение из GitLab или SourceCraft
пока можно собрать в CI, опубликовать образ в реестре и запустить на вкладке «Docker-образ».

Шаги мастера перечислены слева. У пройденного шага видно, что в нём выбрано, а кнопка **«Изменить»**
возвращает к нему. Внизу карточки шага — счётчик «Шаг 1 из 4» и кнопка **«Назад»**. На узком экране шаги
показаны полосой над карточкой.

## Сервер

Шаг **«Сервер»** одинаков во всех вкладках. Выберите сервер из списка, а если сервер один, он выбран
сразу. Если серверов ещё нет, прямо на странице откроется мастер подключения: можно подключить свой VPS или
создать машину в reg.ru Cloud либо Yandex Cloud. Ещё один сервер подключается кнопкой **«Подключить»**.
См. [Подключение сервера](/docs/servers/connect). Вернуться из мастера подключения к списку серверов можно
кнопкой **«К готовым серверам»**.

У каждого сервера видно свободное место на диске. Если места мало, мастер предупредит и предложит
**«Освободить место»**. Сервер, диск которого не удалось проверить, выбрать нельзя: проверьте
SSH-подключение и Docker.

Сервер с пометкой **«Не настроен»** подключён, но DeployCode на нём ещё не установлен, поэтому выбрать его
нельзя. Ссылка **«Перейти к установке»** открывает вкладку «Проверка» на странице сервера, см.
[Если установка не завершена](/docs/servers/connect#если-установка-не-завершена).

Если машина, заказанная в облаке, ещё создаётся, мастер покажет под списком «Сервер … ещё создаётся».
Второй сервер заказывать не нужно: готовый появится в списке сам. Ход настройки откроет кнопка
**«Следить за созданием»**.

Выбрав сервер, нажмите кнопку перехода к следующему шагу, например **«Далее: настройки»**.

## Шаблон или Docker-образ

<Steps>
<Step>

### Выберите, что запустить

На вкладке **«Шаблоны»** выберите шаблон в каталоге. На его странице видно, что будет настроено: образ,
адрес, тома, база и сгенерированные секреты. См. [Шаблоны](/docs/deployments/templates).

На вкладке **«Docker-образ»** образ и его параметры указываются на последнем шаге, **«Образ и запуск»**.
См. [Docker-образ](/docs/deployments/docker-image).

</Step>
<Step>

### Выберите сервер

См. [Сервер](#сервер).

</Step>
<Step>

### Запустите

Проверьте **«Название сервиса»** — его видно в шапке и на плитках. В новом проекте есть ещё поле
**«Название проекта»**.

Нажмите **«Создать и запустить»**. DeployCode создаст проект и сервис, запустит развёртывание и сразу
откроет страницу сервиса: на ней видно, как идёт запуск. У шаблона со своей базой сначала запускается база,
приложение развернётся следом. Как войти в приложение из шаблона, подскажет блок
[«Вход»](/docs/deployments/templates#вход-в-приложение).

</Step>
</Steps>

## Приложение из GitHub

<Steps>
<Step>

### Код

Доступ к GitHub выдаётся через **GitHub App** — персональный токен не нужен.

- Если GitHub ещё не подключён, нажмите **«Подключить GitHub»** и выберите репозитории, которые увидит
  DeployCode. GitHub откроется в отдельном окне. После подключения окно закроется само, а аккаунт
  появится в мастере. См. [Подключение GitHub](/docs/deployments/github).
- Если DeployCode App уже установлен на ваш аккаунт GitHub, но не подключён, мастер покажет
  «DeployCode App уже установлен на …» с кнопкой **«Подключить»** — на GitHub переходить не нужно.
- Выберите **аккаунт GitHub**, **репозиторий** и **ветку** (по умолчанию — основная ветка репозитория).
  Ещё один аккаунт или организация GitHub подключается кнопкой **«Другой аккаунт или организация»**.
- **Путь к приложению** — каталог приложения в репозитории. Для монорепозитория укажите подкаталог,
  иначе оставьте `/`.

Если нужного репозитория нет в списке, нажмите **«Открыть доступ в GitHub»** под полем «Репозиторий».
Если владелец аккаунта приостановил GitHub App или отозвал его доступ, репозитории не загрузятся, и мастер
скажет об этом. Нажмите **«Переподключить»** или выберите другой аккаунт.

DeployCode покажет обнаруженный фреймворк, например «Обнаружено: Next.js». Если в каталоге приложения
лежит файл `Dockerfile`, мастер покажет «Обнаружено: Dockerfile», и образ соберётся по нему, см.
[Сборщик](/docs/deployments/builders#сборщик). Нажмите **«Далее: сервер»**.

</Step>
<Step>

### Сервер

См. [Сервер](#сервер).

</Step>
<Step>

### Настройки

Рабочие значения уже подставлены — проверьте и при необходимости поправьте:

- **Проект** получает имя репозитория, а **Сервис** — имя каталога, из которого собирается приложение
  (`/apps/web` → `web`), или имя репозитория, если приложение в корне. Введённое вами название мастер
  не перезаписывает.
  Поле «Проект» есть только в мастере «Новый проект». Если проект с таким названием уже есть, мастер
  предупредит, что в списках их будет не отличить: кнопка **«Назвать „…-2“»** подставит свободное название,
  а ссылка под предупреждением откроет добавление сервиса в существующий проект.
- **Порт** — порт, который слушает приложение внутри контейнера. По умолчанию `3000`, а если в `Dockerfile`
  последней стадии есть `EXPOSE`, — порт из него. На этот порт поведёт адрес на `deploycode.app`, и его же
  приложение получит в переменной `PORT`. Если среди переменных ниже есть `PORT` с другим значением, мастер
  предупредит и предложит **«Указать …»**. См. [Фреймворки → Порт](/docs/frameworks#порт--главное-что-нужно-проверить).
- **Создать PostgreSQL** и **Создать Valkey** — необязательно. База и хранилище, совместимое с Redis,
  создаются на этом же сервере, а приложение получает их адреса в `DATABASE_URL` и `REDIS_URL`. См.
  [База данных и Valkey](#база-данных-и-valkey).
- **Переменные окружения** — необязательно. По одной в строке, в формате `KEY=value`, можно вставить
  `.env` целиком. Строки с `#` в начале — комментарии. Если адрес в переменной ведёт на ваш компьютер,
  мастер предупредит, см. [ниже](#адреса-с-вашего-компьютера).

Нажмите **«Запустить приложение»**.

</Step>
<Step>

### Запуск

DeployCode последовательно:

| Этап | Что происходит |
| --- | --- |
| Проверяем сервер | Свободное место и иноды на диске |
| Создаём проект и production-окружение | Проект, окружение `production` и сервис, а также PostgreSQL и Valkey, если они отмечены |
| Выдаём домен deploycode.app | Свободный адрес вида `<имя>-<суффикс>.deploycode.app` |
| Запускаем PostgreSQL | Только с «Создать PostgreSQL»: база запускается до сборки, а сборка начнётся, когда база начнёт принимать подключения |
| Запускаем Valkey | Только с «Создать Valkey»: Valkey встаёт в очередь развёртываний раньше приложения |
| Выполняем развёртывание | [Сборка](/docs/deployments/builders) на сервере по `Dockerfile` или через Railpack, обычно 2–6 минут |
| Проверяем контейнеры | Что реплики запустились |
| Подключаем HTTPS | Сертификат Let's Encrypt — после успешной сборки. Этап завершается, когда сервер отдаёт выпущенный сертификат |

Страницу можно закрыть: прогресс сохранён, а развёртывание продолжится на сервере. Ход сборки видно по
кнопке **«Показать логи»**.

</Step>
</Steps>

Когда всё готово, появится экран **«Настройка завершена»** с кнопками **«Открыть сервис»** и
**«Открыть сайт»**. Если отмечен Valkey, запуск завершится, только когда запущен и он. Если панель ещё не
увидела сертификат, экран напишет «Домен настроен, сертификат ещё выпускается». Если браузер предупредит о
сертификате, обновите страницу через минуту.

## База данных и Valkey

На шаге «Настройки» мастер GitHub может создать для приложения базу PostgreSQL и Valkey — хранилище в
памяти, совместимое с Redis, для кеша, сессий и очередей. Отметьте **«Создать PostgreSQL»**,
**«Создать Valkey»** или оба. Они создаются вместе с сервисом: в том же окружении и на том же сервере.

| | PostgreSQL | Valkey |
| --- | --- | --- |
| Имя сервиса | `<имя сервиса>-db` | `<имя сервиса>-valkey` |
| Что запускается | PostgreSQL 17 с томом для данных. Имя базы и пользователь — имя сервиса латиницей, например `my_site` для `my-site`, пароль генерируется | Шаблон [Valkey](/docs/deployments/templates): образ `valkey/valkey:8`, том `/data`, сгенерированный пароль `VALKEY_PASSWORD` |
| Переменная приложения | `DATABASE_URL` — строка подключения к базе | `REDIS_URL` — адрес вида `redis://:<пароль>@<хост>:6379` |
| Когда запускается | До сборки. Сборка ждёт, пока база начнёт принимать подключения | В очереди развёртываний раньше приложения |

`DATABASE_URL` и `REDIS_URL` — переменные приложения типа
[«Ссылка на сервис»](/docs/deployments/variables#ссылки-на-сервисы) по внутренней сети. Пароль никуда не
копируется: значение подставляется при каждом развёртывании, поэтому новый пароль приложение получит со
следующим развёртыванием. Такие ссылки доступны только при запуске, во время сборки этих переменных нет.

Если в переменных есть `DIRECT_URL` (его использует Prisma для миграций), с «Создать PostgreSQL» он
получит тот же адрес новой базы, а значение из переменных не используется.

Свой `DATABASE_URL` в переменных вместе с «Создать PostgreSQL» — ошибка: адрес задаст новая база.
Уберите строку кнопкой **«Убрать DATABASE_URL»** или снимите галочку. Так же с `REDIS_URL` и «Создать
Valkey» — кнопка **«Убрать REDIS_URL»**. Пока конфликт не решён, кнопка «Запустить приложение» недоступна.

### Адреса с вашего компьютера

Мастер проверяет вставленные переменные и предупреждает, если адрес в значении ведёт на компьютер
разработчика: `localhost` и `*.localhost`, `127.0.0.1` и другие `127.*`, `0.0.0.0`, `::1`,
`host.docker.internal`. Приложение с таким адресом развернётся, но на сервере по нему ничего нет, и
первое же подключение не удастся.

| Переменная | Что предложит мастер |
| --- | --- |
| `DATABASE_URL` с `postgres://` или `postgresql://` | **«Создать PostgreSQL»**: строка уйдёт из переменных, а `DATABASE_URL` получит адрес новой базы |
| `REDIS_URL` с `redis://` или `rediss://` | **«Создать Valkey»**: строка уйдёт из переменных, а `REDIS_URL` получит адрес нового Valkey |
| Любая другая | Указать адрес сервиса на сервере или внешний адрес |

Предупреждения запуск не блокируют. Адрес внешней базы мастер не трогает.

## Если что-то пошло не так

**Приложение из GitHub.** Мастер покажет **«Запуск остановлен»** с причиной и кнопкой **«Повторить
запуск»**, а если сборка уже началась — **«Открыть логи»**. Созданные ресурсы сохраняются, поэтому повторный
запуск продолжит с места ошибки. Вторую базу или второй Valkey он не создаёт, а уже запущенные не
разворачивает заново.

Частые причины:

- **«На сервере не хватило памяти»** — см. [Не хватает памяти при сборке](/docs/troubleshooting/builds#не-хватает-памяти-при-сборке).
- **«На сервере недостаточно места»** — вместо повтора мастер предложит **«Освободить место и повторить»**.
- **«Сборка не завершилась»** — откройте логи; частые проблемы собраны в разделе
  [Сборка](/docs/troubleshooting/builds).
- **«PostgreSQL не запустилась»** или **«PostgreSQL запустилась, но за 3 минуты не начала принимать
  подключения»** — откройте базу в проекте, посмотрите её логи и повторите запуск.
- **«Valkey не запустился»** — откройте его в проекте, посмотрите логи и повторите запуск.
- **«Valkey этого запуска удалён»** — обычно это значит, что Valkey перемещён в корзину. Восстановите его
  из [корзины](/docs/structure/trash) и повторите запуск.

**Шаблон, Docker-образ, база данных.** Если сервис не удалось создать, мастер покажет ошибку и останется на
месте — нажмите кнопку ещё раз. Второй проект при этом не создаётся. У шаблона и Docker-образа в
уведомлении об ошибке есть кнопка **«Удалить проект»**, если ваша роль разрешает удалять проекты: она
перемещает созданный мастером пустой проект в корзину. Если уйти со страницы, пустой проект останется, его
можно удалить на странице «Проекты». Если сервис создан, но развёртывание
не запустилось, откроется страница сервиса с сообщением «Сервис создан, запуск не удался».

## Что настроено автоматически

- Окружение `production` в новом проекте.
- [Управляемый домен](/docs/networking/managed-domains) на `deploycode.app` с HTTPS — у всех сервисов с
  веб-интерфейсом. Базе данных и сервису без HTTP домен не выдаётся.
- [Авторазвёртывание](/docs/deployments/github#авторазвёртывание) при пуше в ветку — у приложений из
  GitHub.
- PostgreSQL и Valkey с переменными `DATABASE_URL` и `REDIS_URL` — у приложения из GitHub, если они
  отмечены в мастере.
- У шаблонов — тома, переменные и сгенерированные секреты.

## Новый сервис в существующем проекте

Тот же мастер в проекте называется **«Новый сервис»**, с теми же вкладками. Он открывается кнопкой
**«Новый сервис»** на страницах проекта и в окне [«Что создать?»](/docs/structure/services#окно-что-создать).
Сервис создаётся в окружении, выбранном в [области](/docs/structure/scope), а если окружение не выбрано —
в окружении проекта по умолчанию.

Новые версии приложения из GitHub выкатываются при пуше в ветку или кнопкой **«Развернуть»** на странице
сервиса — см. [Запуск развёртывания](/docs/deployments/github#запуск-развёртывания).
