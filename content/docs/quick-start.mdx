Первый запуск проходит в мастере **«Запустить приложение»**. Он создаёт проект с окружением `production`,
собирает приложение на вашем сервере и выдаёт ему адрес на `deploycode.app` с HTTPS.

## Что понадобится

- Репозиторий на **GitHub**. GitLab и SourceCraft пока не поддерживаются.
- **Сервер**: свой VPS с доступом по SSH под `root` или пользователем с sudo без пароля, либо сервер в
  подключённом облаке — reg.ru Cloud или Yandex Cloud. См. [Требования](/docs/servers/requirements).

<Steps>
<Step>

### Код

Выберите, откуда взять код. Доступ к GitHub выдаётся через **GitHub App** — персональный токен не нужен.

- Если GitHub ещё не подключён, нажмите **«Подключить GitHub»** и выберите репозитории, которые увидит
  DeployCode. См. [Подключение GitHub](/docs/deployments/github).
- Выберите **аккаунт GitHub**, **репозиторий** и **ветку** (по умолчанию — основная ветка репозитория).
- **Путь к приложению** — каталог приложения в репозитории. Для монорепозитория укажите подкаталог,
  иначе оставьте `/`.

DeployCode покажет, какой фреймворк он обнаружил, — например, «Обнаружено: Next.js».

</Step>
<Step>

### Сервер

Выберите сервер из списка или подключите новый кнопкой **«Подключить»**. Если серверов ещё нет, мастер
добавления сервера откроется сам. См. [Подключение сервера](/docs/servers/connect).

У каждого сервера видно свободное место на диске. Если места мало, DeployCode предложит сначала его
освободить.

</Step>
<Step>

### Настройки

Рабочие значения уже подставлены:

- **Проект** и **Сервис** — по умолчанию названы как репозиторий.
- В **«Дополнительных настройках»**:
  - **Внутренний порт** — порт, который слушает приложение внутри контейнера, по умолчанию `3000`.
    См. [Фреймворки → Порт](/docs/frameworks#порт--главное-что-нужно-проверить).
  - **Переменные окружения** — по одной в строке, в формате `KEY=value`. Строки, начинающиеся с `#`, —
    комментарии.

Нажмите **«Запустить приложение»**.

</Step>
<Step>

### Запуск

DeployCode последовательно:

| Этап | Что происходит |
| --- | --- |
| Проверяем сервер | Свободное место и иноды на диске |
| Создаём проект и production-окружение | Проект, окружение `production` и сервис |
| Выдаём домен deploycode.app | Свободный адрес вида `<имя>-<суффикс>.deploycode.app` |
| Выполняем развёртывание | Сборка [Railpack](/docs/deployments/builders) на сервере, обычно 2–6 минут |
| Проверяем контейнеры | Что реплики запустились |
| Подключаем HTTPS | Сертификат Let's Encrypt — после успешной сборки |

Страницу можно закрыть: прогресс сохранён, а развёртывание продолжится на сервере. Ход сборки видно по
кнопке **«Показать логи»**.

</Step>
</Steps>

Когда всё готово, появится экран **«Настройка завершена»** со ссылкой на сайт.

## Если что-то пошло не так

Мастер покажет причину и кнопку **«Повторить запуск»**, а если сборка уже началась — **«Открыть логи»**.
Созданные ресурсы сохраняются, поэтому повторный запуск продолжит с места ошибки.

Частые причины:

- **«На сервере не хватило памяти»** — см. [Не хватает памяти при сборке](/docs/troubleshooting/builds#не-хватает-памяти-при-сборке).
- **«На сервере недостаточно места»** — вместо повтора мастер предложит **«Освободить место и повторить»**.
- **«Сборка не завершилась»** — откройте логи; частые проблемы собраны в разделе
  [Сборка](/docs/troubleshooting/builds).

## Что настроено автоматически

- Окружение `production` в новом проекте.
- [Управляемый домен](/docs/networking/managed-domains) на `deploycode.app` с HTTPS.

## Новый сервис в существующем проекте

В проекте мастер называется **«Новый сервис»** и начинается с шага **«Тип»**: приложение из GitHub или
база [PostgreSQL](/docs/databases/postgres). Сервис создаётся в выбранном окружении.

Новые версии выкатываются кнопкой **«Развернуть»** на странице сервиса — см.
[Запуск развёртывания](/docs/deployments/github#запуск-развёртывания).
