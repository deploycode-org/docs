Первый сервис запускается в мастере **«Новый проект»**. Проект создаётся вместе с этим сервисом — с
окружением `production` и адресом на `deploycode.app` с HTTPS.

Мастер открывается на странице **«Проекты»** — с неё начинается работа после входа: кнопка
**«Новый проект»** в шапке или **«Создать проект»**, пока проектов нет. Ещё один путь — пункт **«Проект»** в
окне [«Что создать?»](/docs/structure/services#окно-что-создать).

## Что понадобится

- **Сервер**: свой VPS с доступом по SSH под `root` или пользователем с sudo без пароля, либо сервер в
  подключённом облаке — reg.ru Cloud или Yandex Cloud. См. [Требования](/docs/servers/requirements).
- **GitHub** — только для приложения из репозитория. GitLab и SourceCraft пока не поддерживаются.

Справа от каталога шаблонов мастер показывает, что уже подключено: сервер и GitHub. Недостающее можно
подключить прямо по ходу мастера.

## Что запустить

Мастер начинается с выбора вкладки:

| Вкладка | Что запускает |
| --- | --- |
| **Шаблоны** | Готовое приложение из [каталога](/docs/deployments/templates): Uptime Kuma, n8n, Umami и ещё 9. Образ, тома и секреты уже настроены |
| **GitHub** | Ваше приложение из репозитория: DeployCode соберёт его на сервере |
| **Docker-образ** | Любой [образ](/docs/deployments/docker-image) из Docker Hub, GHCR или другого реестра, в том числе приватного |
| **База данных** | [PostgreSQL](/docs/databases/postgres) на вашем сервере |

Вкладки **GitLab**, **SourceCraft** и **Compose** помечены «скоро». Приложение из GitLab или SourceCraft
пока можно собрать в CI, опубликовать образ в реестре и запустить на вкладке «Docker-образ».

Шаги мастера перечислены слева. У пройденного шага видно, что в нём выбрано, а кнопка **«Изменить»**
возвращает к нему. Внизу карточки шага — счётчик «Шаг 1 из 4» и кнопка **«Назад»**. На узком экране шаги
показаны полосой над карточкой.

## Сервер

Шаг **«Сервер»** одинаков во всех вкладках. Выберите сервер из списка, а если сервер один, он выбран
сразу. Если серверов ещё нет, прямо на странице откроется мастер подключения: можно подключить свой VPS или
создать машину в reg.ru Cloud либо Yandex Cloud. Ещё один сервер подключается кнопкой **«Подключить»**.
См. [Подключение сервера](/docs/servers/connect). Вернуться из мастера подключения к списку серверов можно
кнопкой **«К готовым серверам»**.

У каждого сервера видно свободное место на диске. Если места мало, мастер предупредит и предложит
**«Освободить место»**. Сервер, диск которого не удалось проверить, выбрать нельзя: проверьте
SSH-подключение и Docker.

Выбрав сервер, нажмите кнопку перехода к следующему шагу, например **«Далее: настройки»**.

## Шаблон или Docker-образ

<Steps>
<Step>

### Выберите, что запустить

На вкладке **«Шаблоны»** выберите шаблон в каталоге. На его странице видно, что будет настроено: образ,
адрес, тома, база и сгенерированные секреты. См. [Шаблоны](/docs/deployments/templates).

На вкладке **«Docker-образ»** образ и его параметры указываются на последнем шаге, **«Образ и запуск»**.
См. [Docker-образ](/docs/deployments/docker-image).

</Step>
<Step>

### Выберите сервер

См. [Сервер](#сервер).

</Step>
<Step>

### Запустите

Проверьте **«Название сервиса»** — его видно в шапке и на плитках. В новом проекте есть ещё поле
**«Название проекта»**.

Нажмите **«Создать и запустить»**. DeployCode создаст проект и сервис, запустит развёртывание и откроет
страницу сервиса: на ней видно, как идёт запуск.

</Step>
</Steps>

## Приложение из GitHub

<Steps>
<Step>

### Код

Доступ к GitHub выдаётся через **GitHub App** — персональный токен не нужен.

- Если GitHub ещё не подключён, нажмите **«Подключить GitHub»** и выберите репозитории, которые увидит
  DeployCode. См. [Подключение GitHub](/docs/deployments/github).
- Выберите **аккаунт GitHub**, **репозиторий** и **ветку** (по умолчанию — основная ветка репозитория).
- **Путь к приложению** — каталог приложения в репозитории. Для монорепозитория укажите подкаталог,
  иначе оставьте `/`.

DeployCode покажет обнаруженный фреймворк, например «Обнаружено: Next.js». Нажмите **«Далее: сервер»**.

</Step>
<Step>

### Сервер

См. [Сервер](#сервер).

</Step>
<Step>

### Настройки

Рабочие значения уже подставлены — проверьте и при необходимости поправьте:

- **Проект** и **Сервис** — при выборе репозитория получают его имя, если вы не ввели своё. Поле «Проект»
  есть только в мастере «Новый проект».
- **Порт** — порт, который слушает приложение внутри контейнера, по умолчанию `3000`. На него поведёт
  адрес на `deploycode.app`. См. [Фреймворки → Порт](/docs/frameworks#порт--главное-что-нужно-проверить).
- **Переменные окружения** — необязательно. По одной в строке, в формате `KEY=value`, можно вставить
  `.env` целиком. Строки с `#` в начале — комментарии.

Нажмите **«Запустить приложение»**.

</Step>
<Step>

### Запуск

DeployCode последовательно:

| Этап | Что происходит |
| --- | --- |
| Проверяем сервер | Свободное место и иноды на диске |
| Создаём проект и production-окружение | Проект, окружение `production` и сервис |
| Выдаём домен deploycode.app | Свободный адрес вида `<имя>-<суффикс>.deploycode.app` |
| Выполняем развёртывание | Сборка [Railpack](/docs/deployments/builders) на сервере, обычно 2–6 минут |
| Проверяем контейнеры | Что реплики запустились |
| Подключаем HTTPS | Сертификат Let's Encrypt — после успешной сборки |

Страницу можно закрыть: прогресс сохранён, а развёртывание продолжится на сервере. Ход сборки видно по
кнопке **«Показать логи»**.

</Step>
</Steps>

Когда всё готово, появится экран **«Настройка завершена»** с кнопками **«Открыть сервис»** и
**«Открыть сайт»**.

## Если что-то пошло не так

**Приложение из GitHub.** Мастер покажет **«Запуск остановлен»** с причиной и кнопкой **«Повторить
запуск»**, а если сборка уже началась — **«Открыть логи»**. Созданные ресурсы сохраняются, поэтому повторный
запуск продолжит с места ошибки.

Частые причины:

- **«На сервере не хватило памяти»** — см. [Не хватает памяти при сборке](/docs/troubleshooting/builds#не-хватает-памяти-при-сборке).
- **«На сервере недостаточно места»** — вместо повтора мастер предложит **«Освободить место и повторить»**.
- **«Сборка не завершилась»** — откройте логи; частые проблемы собраны в разделе
  [Сборка](/docs/troubleshooting/builds).

**Шаблон, Docker-образ, база данных.** Если сервис не удалось создать, мастер покажет ошибку и останется на
месте — нажмите кнопку ещё раз. Второй проект при этом не создаётся. Если после ошибки уйти со страницы,
проект останется пустым: удалите его на странице «Проекты». Если сервис создан, но развёртывание
не запустилось, откроется страница сервиса с сообщением «Сервис создан, запуск не удался».

## Что настроено автоматически

- Окружение `production` в новом проекте.
- [Управляемый домен](/docs/networking/managed-domains) на `deploycode.app` с HTTPS — у всех сервисов с
  веб-интерфейсом. Базе данных и сервису без HTTP домен не выдаётся.
- [Авторазвёртывание](/docs/deployments/github#авторазвёртывание) при пуше в ветку — у приложений из
  GitHub.
- У шаблонов — тома, переменные и сгенерированные секреты.

## Новый сервис в существующем проекте

Тот же мастер в проекте называется **«Новый сервис»**, с теми же вкладками. Он открывается кнопкой
**«Новый сервис»** на страницах проекта и в окне [«Что создать?»](/docs/structure/services#окно-что-создать).
Сервис создаётся в окружении, выбранном в [области](/docs/structure/scope), а если окружение не выбрано —
в окружении проекта по умолчанию.

Новые версии приложения из GitHub выкатываются при пуше в ветку или кнопкой **«Развернуть»** на странице
сервиса — см. [Запуск развёртывания](/docs/deployments/github#запуск-развёртывания).
