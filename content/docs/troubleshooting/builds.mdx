## Railpack не определил язык

Railpack ищет характерные файлы (`package.json`, `requirements.txt`, `go.mod`, `composer.json`,
`index.html`) в корне или в [пути сборки](/docs/deployments/builders#путь-сборки). Проверьте, что путь
сборки указывает на каталог приложения. См. [Фреймворки](/docs/frameworks).

## Не хватает памяти при сборке

Панель сообщит, что на сервере не хватило памяти, а в логе будут строки вроде `exit code 137`,
`cannot allocate memory` или `JavaScript heap out of memory`.

Сборка выполняется на том же сервере, где работают приложения, и обычно требует заметно больше памяти,
чем работающее приложение. Например, `next build` может занимать 1,5–2 ГБ даже для небольшого сайта.

Что можно сделать:

- **Увеличить память сервера** — самый надёжный вариант.
- **Добавить файл подкачки**, если увеличить память нельзя. Сборка станет медленнее, но перестанет
  падать:

  ```bash
  sudo fallocate -l 2G /swapfile
  sudo chmod 600 /swapfile
  sudo mkswap /swapfile
  sudo swapon /swapfile
  echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  ```

- **Снизить потребление самой сборки.** Для Next.js: собирать через webpack (`next build --webpack`) и
  ограничить число воркеров (`experimental.cpus: 1` в `next.config`).
- **При `JavaScript heap out of memory`** — поднять лимит Node.js переменной приложения
  `NODE_OPTIONS=--max-old-space-size=2048`, если на сервере есть свободная память.

## Собирается не то, что ожидалось

Переопределите команды и результат сборки в настройках «Сборка и запуск» — см.
[Сборка (Railpack)](/docs/deployments/builders).
